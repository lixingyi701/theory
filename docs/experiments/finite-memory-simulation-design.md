# 有限记忆恢复理论的受控仿真设计

更新：2026-10-23。状态：设计完成，Monte Carlo 尚未执行。本轮先完成[模型、命题与证明](../research/finite_memory_recovery_analysis.md)，并进行精确代数核对。仿真参数均由机制问题设定，不使用 ALFWorld 结果拟合。

## 1. 仿真要回答什么

| 理论对象 | 需要区分的机制 | 主要输出 |
|---|---|---|
| 命题 1：期望尝试数 | 旧条目退出与新反思重述；$\lambda$ 和 $\rho$ 的不同作用 | $T_r$、$T_W-T_0$、含错阶段时长 $L_r$ |
| 命题 2：预算内增益 | 窗口造成成功机会出现时间不同，不能沿用持续可见模型的单调性 | $V_b(0)$、$V_b(W)$、$\Delta_b$ 随预算的曲线 |
| 信息／位置反例 | 纠正保留内容，同时占用容量；删除改变其他信息的退出时间 | 纠正与删除的排序、有效线索可见时长 |
| 命题 3：影响上界 | 起始差异经新反思继续传递，而非仅由原条目存留决定 | 位置差异概率、成功率差、界的松紧 |

精确递推是给定人工机制的参照值；Monte Carlo 检查独立轨迹实现与它是否一致。理论结论由证明建立，不能把仿真一致解释为真实 Reflexion 满足假设。

## 2. 第一组：精确可解的错误生成／重述模型

使用理论文档第 3 节的 $W+1$ 状态转移，并独立实现完整二值 FIFO。参数扫描为

| 参数 | 取值 |
|---|---|
| 窗口容量 $W$ | $1,2,3,5,8$ |
| 不含目标错误时成功概率 $p$ | $0.2,0.5,0.8$ |
| 含目标错误时成功概率 $q$ | $0,0.02,0.1$ |
| 不含错起点失败后生成错误的概率 $\lambda$ | $0,0.25,0.5,0.75,1$ |
| 含错起点失败后重述错误的概率 $\rho$ | $0,0.25,0.5,0.75,0.9$ |
| 报告预算 $b$ | $1,2,3,4,6,10,20,40,80,160$ |

共 1125 个参数条件，两个主要起点为 $r=0,W$。精确递推计算至 160；闭式期望与独立线性方程解比较。额外单列 $q=0,\rho=1$ 的不退出边界，不把它混入有限期望均值。

Monte Carlo 首批固定八个参数条件：

| $W$ | $p$ | $q$ | $\lambda$ | $\rho$ | 作用 |
|---:|---:|---:|---:|---:|---|
| 3 | .5 | 0 | 0 | 0 | 命题 2 的无错误生成端点 |
| 3 | .5 | 0 | 1 | 0 | 命题 2 的必生成端点 |
| 3 | .5 | .02 | 0 | 0 | 含错状态成功概率 $q>0$ 时的反例 |
| 3 | .5 | .02 | 1 | 0 | 含错状态成功概率 $q>0$ 时的反例 |
| 3 | .5 | 0 | .5 | .5 | 错误重述后的退出 |
| 3 | .5 | 0 | .5 | .9 | 较长含错阶段与截断 |
| 1 | .5 | .02 | .5 | .5 | 短窗口 |
| 5 | .5 | .02 | .5 | .5 | 较长窗口 |

每个条件分别从 $r=0,W$ 开始，各 10000 条轨迹，由十个固定种子各生成 1000 条。每条最多 160 次任务尝试。共 160000 条轨迹，所有条件均保留，不按结果删改。

输出包括每个预算的成功概率、成功概率差和首次成功时间。未成功轨迹在 160 处右删失；不能只对已成功轨迹平均后称为 $T_r$。统一报告 $\mathbb E[\min(\mathcal T,161)]$，其精确参照为 $\sum_{b=0}^{160}[1-V_b(r)]$；完整期望单独由解析式／线性方程计算。高 $\rho$ 条件下，有限预算记录可能与完整期望相差很大，这正是需要展示的尾部。

## 3. 第二组：正确说明、有效线索与删除位置

条目使用 $(e,c,h)$ 三个二值标记，含义见理论文档；$\bot$ 为独立空位符。取 $W=3$，包括短窗口在内共有 $1+8+8^2+8^3=585$ 个类型状态。

使用一组共同的人工机制，而不是为每种恢复另设参数。记 $I_E,I_C,I_H$ 为相应内容是否可见，令

$$
p(M)=\operatorname{clip}_{[0,1]}
(p_0-d_E I_E+d_C I_C+d_H I_H-d_X I_E I_C),
$$

$$
g(M)=\Pr(e_J=1\mid M,Y=0)
=\operatorname{clip}_{[0,1]}[\lambda+(\rho-\lambda)I_E-s_C I_C].
$$

在给定新反思是否含错后，再按

$$
\Pr(c_J=1\mid e_J=1,M,Y=0)=\chi,\qquad
\Pr(c_J=1\mid e_J=0,M,Y=0)=\kappa,
$$

$$
\Pr(h_J=1\mid e_J,c_J,M,Y=0)=\nu_{e_J,c_J}
$$

生成条目。这样得到完整的八类别联合分布，允许错误与正确说明共存，也允许有效线索与它们相关；不要求三个标记独立。

固定参考参数为 $p_0=.4,d_E=.3,d_C=.05,d_H=.1,d_X=0$，$\lambda=.1,\rho=.5,s_C=.1$，$\kappa=.2,\chi=0$，四个 $\nu$ 均为 $.2$。这些参数用于隔离机制，没有真实概率估计的含义。

主要起点为 $(H,E,N)$ 与 $(N,EH,N)$，其中 $EH=(1,0,1)$。对唯一含错条目分别执行：保留、局部纠正、移除错误命题但不添加正确说明、替换整条为真实 $N$、删除整条。五种操作用于分离不同作用：

- 局部纠正与只移除错误命题：正确说明的作用。
- 保留有效线索的移除与整条替换为 $N$：同条有效信息的作用。
- 整条替换为 $N$ 与整条删除：占用容量和位置变化的作用。

先用理论第 6 节的固定反例复现排序反转，再对参考机制逐项改变：$d_H\in\{0,.1,.3\}$、$s_C\in\{0,.1,.4\}$、$d_X\in\{0,.1,.3\}$、$\chi\in\{0,.25,.5\}$。每次只改变一项，不做四维笛卡尔积；参考条件加八个非参考变体，共九个条件、两个起点、五种操作。预算沿用第一组，精确 FIFO 递推为主。

第二组另对理论第 6 节的纠正和删除各生成 10000 条 Monte Carlo 轨迹，种子和预算沿用第一组。其余扫描先保存精确结果，只有在轨迹实现与精确参照出现差异时排查实现，不按预期排序追加有利参数。

这里不预设纠正、删除或某种压缩状态普遍更好。若某个机制改变排序，应记录改变的是正确说明、有效线索、冲突还是条目占用，并报告首次发生排序变化的预算。

## 4. 第三组：起始影响与更新敏感度

先使用易于核对常数的二值窗口：

$$
p(M)=.8-.1\sum_{i=1}^3 e_i,\quad
\Pr(e_J=1\mid M,Y=0)=.1+.1e_1+.1e_2+.2e_3.
$$

这给出 $\alpha=(.1,.1,.1)$、$\beta=(.1,.1,.2)$、$p_{\min}=.5$。对全部八个起点的 64 个有序配对，逐预算核对命题 3 的界。每个起点各生成 10000 条轨迹，沿用十种子分组，用共同随机数记录辅助链的槽位差异概率；相同编号的轨迹形成配对。成功率差与辅助记忆差异分别画图。

再单列两种机制边界：$K$ 不依赖记忆（$\beta=0$）和新反思确定复制最新目标错误标记（$\beta=(0,0,1)$）。前者检查直接窗口移出，后者展示有限容量不能保证影响衰减。边界例使用明确写出的转移，不从观察到的短曲线反推统一敏感度常数。

## 5. 随机化、数值检查与工件

在服务器既有 NumPy 1.26.4 环境中使用 `Generator(PCG64(seed))`，十个种子固定为 21023 至 21032。每次尝试按固定顺序使用成功随机数和失败反思随机数；配对分支可共享对应尝试的随机数，但分别保持正确边际分布。共同随机数只用于降低差值方差，不作为真实 LLM 可严格配对的假设。

每个 Monte Carlo 成功概率报告 95% Wilson 区间；与精确参照的程序一致性检查预先采用 Hoeffding 容差 $\sqrt{\log(2m/.01)/(2n)}$，其中 $m$ 是事先固定的全部曲线比较数，$n=10000$。成功概率差的误差界取对应两个概率界之和。超界先排查转移、随机数和统计实现，不解释为推翻已证明的数学命题。

正式仿真脚本尚待实现，当前可执行的是 `scripts/check_finite_memory_analysis.py`。下一轮实现独立轨迹采样与精确核计算后，在新目录 `runs/finite-memory-simulation-<run-id>/` 保存参数、源码哈希、运行环境、精确曲线、随机种子分组计数、删失记录及失败日志。公共汇总放入 `repro/theory-20261023/`，原始轨迹留在服务器。单次 CPU 批次上限 30 分钟，超时保存已完成条件与未完成清单，不自动减少轨迹数或替换参数。

仿真不调用 LLM、不占用模型显卡，也不使用 134 holdout。真实校准随后重点检查：$C/H$ 是否有额外作用、成功与生成概率是否依赖条目年龄／任务、错误是否在退出后再次出现，以及窗口类型是否概括了历史。已有 ECC／CCE 结果作为开发资料，不作为新的冻结验证。
