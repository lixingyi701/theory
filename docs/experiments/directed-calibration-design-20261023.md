# 真实 Agent 定向校准：首批设计

CPU 仿真已经检查了有限记忆模型内部的推导和预测。真实 Agent 校准接下来检查模型的假设：失败后生成什么反思，错误是否被重述，以及位置与上下文是否改变转移规律。本批使用四个已有开发任务，目的是识别机制和缩小后续模型范围。

## 记忆构造

仍使用已冻结的 Qwen3-8B BF16、官方非思考采样配置和原版 Reflexion 执行函数。每轮最多 49 次决策，失败后由原版反思器追加一条反思；下一轮读取最近三条。模型、提示包装、动作表示映射和任务数据均保持其固定版本。

按从旧到新的顺序表示记忆：E 是包含目标错误的原始反思；C 只纠正其中经过审核的目标命题，保留其他建议；N 是一条实际输入的通用计划 `Plan: I should continue working on the household task.`，其行为影响需要测量。空列表表示没有反思，和 N 分开统计。

H 是人工构造的位置记录，内容来自 Agent 先前实际观察到的物体位置。构造前，用三个预定种子重置环境并执行公开的导航命令，检查位置事实仍然成立。H 没有使用规划器或评估器的隐藏状态。它是否有助于完成任务，由结果判断。

## 三组条件

| 面板 | 起始条件 | 任务与种子 | 每个条件的尝试预算 | 要回答的问题 |
|---|---|---|---|---|
| 生成与重述 | `[E]`、`[C]`、`[N]`、`[]` | 四个任务 × 三个种子 | 一次 | 含错与不含错起点的失败后反思有什么差别？纠正和没有建议是否相同？ |
| 恢复与信息 | `[H,E,N]`、`[H,C,N]`、`[H,N,N]`、`[H,N]`、`[N,N,N]` | 四个任务 × 两个种子 | 最多两次，成功即停止 | 纠正、替换和删除的收益有何差别？位置线索是否有用？ |
| 错误位置 | `[E,N,N]`、`[N,N,E]` | 四个任务 × 两个种子 | 最多两次，成功即停止 | 内容多重集相同时，错误所在位置及其被移出窗口的时间是否重要？ |

种子预先固定为 1701、1702、1703，后两组只使用前两个。共 104 个起始条件，最多 160 次真实尝试。相同任务、种子和面板内的比较放在同一个模型副本；块的分配与条件顺序按预定规则轮换。三张空闲卡各运行同配置服务。采集前，每个副本执行相同的两个已记录种子请求，核对配置与输出；这只是部署检查。

## 观测与分析

首先记录任务是否完成、实际动作及环境反馈，再逐条审核新反思的目标命题，标为错误 E、正确 C、未提及 U 或含义不明 A。只有失败并确实写出新反思的尝试，进入相应的反思转移分母。起始可见记忆不含错误而新反思含错，称为“生成”；起始记忆已含错误而新反思含错，称为“重述”。第二次尝试按当时实际可见记忆重新编码，不能沿用初始标签。

报告每个任务、条件和种子的记录，比较同任务同种子的首轮及两次预算成功结果。种子重复只提供任务内变异信息；本批仍只有四个基础任务。先检查上下文、位置及任务依赖，再决定哪些参数能够共享。正式跨恢复条件预测需要另行冻结参数、预测和新的基础任务；134 个留出任务继续封存。

本批不把 N 视为必然无效，也不把 H 视为必然有益。`[H,N,N]` 与 `[H,N]` 在反思条数、文本长度及 H 的移出时间上同时不同；该比较测量具体恢复操作的综合效果。`[H,N,N]` 与 `[N,N,N]` 单独检查构造位置线索的影响。

## 执行边界与记录

本批单独建立预算合同：最多新增 6000 次本地模型调用（含副本检查）、最长三小时。三个采集进程使用加锁的共享调用预留计数；未知结果的请求停止检查，不自动重发。完整请求、回复、环境轨迹与反思保存在服务器；仓库发布协议、哈希、审核标注和汇总。未完成尝试单独报告，不计为失败或无错误。

协议：`repro/reflexion-20261023/directed-calibration-protocol.json`。准备和执行入口分别为 `scripts/prepare_directed_calibration.py` 与 `scripts/run_directed_calibration.py`。所有起点、种子、预算、条件和代码哈希在新模型调用前冻结。
