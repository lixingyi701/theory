# 四次尝试预算：区分记忆更新与固定起点近似

日期：2026-10-25。依据[新任务验证](shared-validation-20261025.md)、[已有更新记录诊断](update-diagnostic-20261025.md)和[近邻比较](../research/related-work-positioning-20261025.md)。本页给出下一批真实验证的设计；任务清单与CPU精度规划已生成，尚未开展新的Agent采集。

## 1. 要区分的预测

沿用参数摘要`4826508a8a850c983bdd10a91dae065ed544674e7b9c8bc8bd6fa4a6fb9778b5`，比较两个固定预测器：完整模型在失败后推进可见窗口并对新反思积分；简化预测器保留相同的成功系数、任务潜变量和先验，但每次按起始记忆计算成功概率。所有真实轨迹仍运行原生Reflexion，简化预测器不是另一个Agent执行分支。

| 起点 | 完整模型四次成功概率 | 固定初始记忆预测 |
|---|---:|---:|
| [N,C,N] | 56.44% | 79.72% |
| [N,N,N] | 56.44% | 79.72% |
| [E,N,E] | 19.92% | 22.52% |
| [E,N,C] | 33.32% | 24.02% |
| [E,N] | 22.42% | 21.86% |

主要比较使用前两种起点：两预测器相差23.28个百分点，比两次预算更容易区分。后三种起点检查一次恢复操作的后续表现；特别是纠正和删除会改变原始E的退出时间。三条窗口经过三次失败写入后，初始最新条目才会在第四次尝试前退出。新写入条目仍可能包含E，因此按原始条目身份和新文本语义分别记录。

以上来自原参数的精确递推，不是真实Agent结果。四次过程还将进入含两条或三条原生新反思的状态，超出旧校准最多一次更新的主要支持范围；验证同时检验这一状态外推，不预设它成立。

## 2. 新任务、两类样本与种子

已从未调用的训练游戏中选出81个加热任务，覆盖全部27个非封存场景。场景包括原18个校准场景和九个验证场景；任务ID、game摘要与trajectory摘要均与既有任务分离。这里的目标是新任务和新预算预测，不是全新场景泛化。

每景先取两个任务，再按固定场景哈希顺序循环补至81；每个场景内按任务哈希选取，不读取结果。FloorPlan4和26只有两个合格任务，仍予保留；FloorPlan27和21各取四个，其他场景各三个。评分以场景等权，避免任务较多的场景获得更大权重。

- **主要样本：** 全部81任务，起点[N,C,N]与[N,N,N]，种子2130、2131完整交叉，共324条轨迹。
- **恢复样本：** 各景固定哈希最前的一个任务，共27任务；另加[E,N,E]、[E,N,C]、[E,N]，同样交叉两个种子，共162条轨迹。这些任务同时在主要样本中。

总计486条轨迹，最多1944次尝试；成功即停。各条件不再绑定独有种子，同任务的同一种子在各条件重复使用，分析时将其配对并保留共同随机性。任务、种子和尝试均不作为相互独立的场景样本。起点顺序在任务内轮换，实际顺序须在执行协议中保存。

原作者函数、Qwen3-8B BF16、采样、动作接口、49决策预算、一次失败追加一条反思和最近三条可见规则全部沿用。只在起点进行恢复干预，之后不重复纠正或删除。原134任务留出不启用。

## 3. 主要指标与判断

主要事件为是否在四次内成功。对主要样本，计算固定起点预测损失减完整更新预测损失：

\[
D_i=(\widetilde V_4(M_i)-Y_i)^2-(V_4(M_i)-Y_i)^2.
\]

先在任务内平均两种起点和两个种子，再在场景内平均任务，最后等权平均27个场景。主要区间采用场景配对Student t95%，自由度26，临界值2.055529439；整场景bootstrap作为补充，20000次、种子2026102504。区间下端大于0支持完整更新预测，上端小于0支持固定起点近似，跨0则尚未分辨。

该比较针对两个具体预测器，不单独证明更新核唯一或状态充分。补充指标包括1—4次成功曲线、相同任务混合的常数基线、无任务混合模型、恢复样本中的纠正／删除／保留差异，以及各场景误差。补充对照不替换主要指标，也不由结果重新选择主要起点。

新反思标注用于后续条件成功和更新诊断，采用E/C/B/U/A，并区分记忆暴露、相关错误动作尝试、环境接受及任务成功。主要评分只用原生成功事件。截断和形式错误均保留；未知调用不自动重发，缺失不填零，未完成矩阵不作完整验证评分。

## 4. 样本精度与运行成本

对主要样本，两种预测均固定，期望Brier差随真实四次成功率q线性变化；二者期望损失相等的q约为68.08%。因此，实际成功率若接近此处，两者会难以区分，这是允许出现的实验结论。

已运行每个情景10000次的Beta-Binomial规划模拟，按实际27场景任务数和每任务四条主要轨迹生成相关成功事件。下表是在真实成功率等于完整模型56.44%时，主要区间支持完整模型的模拟比例：

| 假设场景相关 | 假设场景内同任务额外相关 | 支持完整模型的模拟比例 | 区间半宽中位数 |
|---|---:|---:|---:|
| 0.02 | 0.10 | 91.46% | 0.03244 |
| 0.05 | 0.25 | 76.97% | 0.03969 |
| 0.10 | 0.50 | 58.39% | 0.04912 |

相关参数是规划假设。若真实成功率为65%，支持完整模型的比例只有约7%—13%；实际落在两预测之间时，本批可能仍无定论。81任务的安排用于提高场景覆盖与任务精度，不声称保证80%功效，也不在采集后为达到显著而持续扩样。

冻结模型给出的期望尝试数约1411次。沿用上一批每次尝试约41.64调用及四服务实测吞吐，预计约58768次调用、5.69小时；这是资源估计，实际由成功停止、生成速度和可用卡数决定。拟定整批上限100000次新调用、43200秒，包含副本核对与失败请求；旧预算保持关闭。
