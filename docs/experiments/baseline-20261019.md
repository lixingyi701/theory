# 基础 Agent 与仪器化预检 v1（2026-10-19）

本方案在新一轮 LLM 调用之前写定。目标是选择一个可用且可追溯的研究骨干，并检验显式记忆/hook 是否损害能力。它不是 ReAct/RIR 成绩复现，也不是错误传播/恢复实验。

## 可追溯依据与边界

- [ReAct 原论文 §4 / Appendix A.1](https://arxiv.org/html/2210.03629v3)：ALFWorld 使用带稀疏思考的人工训练示例；主文 PaLM 与附录 GPT-3 的成绩不可混称。
- [公开 notebook，固定 commit 6bdb3a1](https://github.com/ysymyth/ReAct/blob/6bdb3a1fd38b8188fc7ba4102969fe483df8fdc9/alfworld.ipynb)：每类型取 `react_{type}_1` 后接 `_0`；保留累积交互；最多49次 decision；温度0、top_p 1、100输出token、换行停止。我们直接固定示例文件字节并保留其 MIT 许可证。
- [RIR §5.1](https://arxiv.org/html/2609.18304v1)：基础 Agent 使用 AgentScope；骨干为 Qwen3-14B/DeepSeek-V3；方法之间共用模型与预算。公开材料未给齐精确提示/预算配置，因此本项目不称严格 RIR 复现。
- [固定 ALFWorld 语法](https://github.com/alfworld/alfworld/blob/aaba6870f86c5be6a08a491f32a50b906227bc3e/alfworld/data/alfred.twl2#L199)：放置命令是 `move {o} to {r}`。示例中的 `put X in/on Y` 经固定字符串语法转换后提交；不读取 admissible commands 来替模型选动作。记录模型命令与提交命令。
- [Qwen3-8B 模型卡](https://huggingface.co/Qwen/Qwen3-8B/tree/b968826d9c46dd6066d109eabc6255188de91218)：使用固定 BF16 非 thinking chat 路径。本轮温度0遵循公开 ReAct 解码，偏离 Qwen 建议的非 greedy 采样，属于明确适配选择；不宣称最佳8B配置。

## 冻结设置

`configs/react_base.json` / `react_instrumented.json`：同一 Qwen3-8B revision、示例、完整历史、解码、seed42、49 decisions、49实际动作上限；think 占用 decision 和调用，不改变环境。原 notebook 将 think 送进环境后用 OK 覆盖反馈，本适配在 runner 内生成 OK，不增加环境 moves。每次策略最多100 token，换行停止，不重试策略格式。Chat 模板代替旧 completion 接口是另一项明确差异。

base 不调用记忆模型。memory / sham 在每个新环境观察前更新最多16条结构化记忆，使用同一个模型与解码，最多256输出token，一次格式重试。两者保留与 base 相同的完整交互历史；只增加显式记忆输入。全条件调用硬上限147，辅助调用实际消耗分别报告，不能把额外推理成本隐藏成等算力。sham 在第0–48个动作前首次可验证真位置事实做等内容替换；真值只用于 hook 选择，不进入提示。相同任务/decision/角色使用相同随机种子。

远程服务在首个新实验调用前将 context 固定为32768（原8192）。固定模型 config 的原生 max_position_embeddings=40960；不启用 RoPE 外推。原因是两条完整示例和49步累积历史必须保留，不能为适应旧服务限制默默截掉历史。所有条件使用相同服务。

## 数据与预先门槛

- 开发集：train 中六类各2个任务，共12个互异 floor_plan；排除原 pilot 的24个场景和能用公开初始布局匹配到的可能示例场景。固定选择 seed20261019，不按任务结果/参考长度筛选。
- 上游示例未发布 task/scene ID，跨数据版本不能完全核实示例场景独立性。因此开发集只用于工程选择，不能报告泛化估计。未知匹配必须保留在清单，不能写成“示例泄漏已完全排除”。
- 泛化留出：完整官方 valid_unseen 134任务 / 4场景全部封存，不参与本轮模型调用和调参；所有同场景任务保持同分区。这也避免把仅4场景误写成134个独立场景。
- 开发12任务先通过同一真实 backend 的10任务/40次 restore 审计，不放宽已有门槛。
- 首先跑 base 12；**至少6/12成功且至少4/6任务类型有成功**才进入仪器化比较。这是预设工程可用性门槛，不是论文统计结论。
- 若8B不通过：保留完整分母和失败，不调提示、不删任务；可按同一协议评估已固定revision的14B，作为预定模型选择。模型选择只用开发集。两者均失败则停止，不启动因果矩阵。
- base 通过后，同一12任务运行 memory 与 sham。memory 相对 base 最多损失1个成功任务，且至少6个成功、覆盖至少4类；否则仪器化门槛失败。报告全部成败转移，不只给均值。
- sham 与 memory 应逐任务有完全相同策略提示与轨迹；至少6/12任务实际触发等内容hook。hook外的浮点非确定性若导致分歧，先单独诊断，不将其归为干预效应。
- 不确定请求立即停，不自动网络重发；格式失败、截断、动作/decision/调用预算、基础设施错误分别计数。若前6个任务全失败，提前停止剩余6个，标记缺失，诊断后另建版本；不得把缺失计为失败。

## 下一节点

上述门槛通过后仍不直接宣称理论成立。先固定 instrumentation 与支持的任务范围，检查完整留出协议，再实现根事实注入、配对前缀和 R0–R3；控制前缀状态/剩余预算，记录错误写入、后续读取、行动影响和最终结果。还需独立短任务拟合与长度/恢复留出预测模块。尚未实现的部分必须保留为未完成。

## 旧 pilot 的接口诊断

原27/48 episode 均失败；其109次 `put ... in/on ...` 提交中0次是当前语法允许的动作，仅1次在当时状态把语法改为 `move ... to ...` 后属于 admissible。这说明语法错误是真实缺陷，也说明其余108次还有位置/持有/状态等问题；不能声称一个转换就能解释或修好所有失败。原记录不回写、不续跑，只作为工程失败证据。
