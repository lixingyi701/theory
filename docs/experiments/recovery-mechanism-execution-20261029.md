# 原生目标错误恢复实验：编辑、评价与执行协议

日期：2026-10-29。接续[恢复机制设计](recovery-mechanism-design-20261029.md)。本页在首个模型请求前固定实验内容；准备阶段没有Agent调用或参数拟合。

## 数据与五种干预

51任务、23场景，每任务一个原生父失败，来源及身份选择见[父记录清单](../../repro/reflexion-20261025/recovery-mechanism-parents-20261029.json)。父尝试从三条通用反思开始，失败后新增一条被标为目标错误E的原生反思。当前可见窗口为`[N,N,E]`，只有新增条目被标记为目标错误。任务及语义标签已有开发使用，本次属于前瞻的机制干预开发，不作为独立新任务验证。

逐条阅读全文，固定78个编辑区间；处理所有识别出的目标微波炉位置要求及其重复表述。五条件为原文、目标错误等义改写、纠正目标命题、删去目标命题、整条删除。前三种编辑使用相同源区间，区间外保持原字节；删句只移除所选区间，整条删除移除完整新增反思。前四条件起点有一条原生条目，整条删除起点有零条，全部从同一逻辑第二次尝试开始。

部分错误句同时包含设备关闭、命令示例或后续放置要求，编辑效果包含这些具体文字变化，不等同于一个脱离措辞的纯抽象命题效应。其他炉灶、烤面包机、设备占用和原因推测仍可能保留；纠正组并未得到完整正确计划。编号列表在删句后可能留下编号间隔，不把删除视为格式或长度无影响。

文字使用单个Codex全文阅读与配对自检，没有独立盲评或第二人工复核。原生E标签来自前期标注；目标类别、完整文字及变化都保留，后续可以核查这些语义判断。

## 接口与精度

两新种子为2190、2191。102次官方环境重置与父任务起始观察一致，255个原生首请求均核对完整可见记忆、标题和条目编号。使用同一Qwen3-8B BF16、非思考包装、推荐采样、作者actor/reflector和每次49个决策。

首请求的纠正减等义改写长度差为−14至+4个Qwen词元，没有用额外任务信息填齐长度。所有请求在32768上下文内预留256输出词元。原文与等义改写、纠正与删句、删句与整条删除的差异分别保留，不能把长度记录当成长度效应已排除。

用前期原生即时纠正的任务差异作场景波动情景，23场景的97.5%区间预计半宽约20.73个百分点；用旧四次纠正／删除差异作情景，约23.44个百分点。两来源与本批不同，这些是精度情景，不是功效保证。本批聚焦明确错误的恢复机制与较大收益，不以分辨约2个百分点的操作差异为设计目标。固定51任务及两个种子，不按中途结果增减样本；正式独立验证另行设计。

## 四次恢复预算与共同前缀对照

每个父起点运行五条件、两个种子，共510条主轨迹。预算指恢复后最多四次新尝试，对应逻辑编号2至5，不包含既有父失败。每次失败照常新增反思，成功即停止，作者读取最近三条。后续不持续纠正，也不修复模型输出动作。

另有102条派生的纠正条目保留策略：与普通纠正共用前三次尝试。如果已成功，复制停止结果，不新增调用；若连续三次失败，第四次在相同环境、同种子下，将普通窗口`[J1,J2,J3]`改为`[C,J2,J3]`，仅增加一个第四次分支。这里C是本任务起始纠正后的完整原生条目。比较的对象是保留原纠正条目代替最早新反思，不能假定J1没有作用。

保留策略在采集前固定，主轨迹和派生结果共享的前三次失败不会被记录为重复采集。最多产生2142次新尝试，主轨迹的多轮更新和派生第四次均由原生环境结果评价。

## 主要评价与冻结预测

共同主要比较为恢复后四次内成功率的“纠正−错误等义改写”和“纠正−整条删除”。先平均任务内两个配对种子，再平均场景内任务，最后23场景等权。两项分别使用场景配对t97.5%区间，自由度22，Bonferroni控制共同主要比较的家族错误率。区间跨零时保留未分辨的结果，不换用次要指标宣称主要收益。

预定次要结果包括六种策略的一至四次成功曲线、其他配对差、条目保留策略、加热和错误操作顺序、调用与截断。次要逐点t95%区间用于描述，不从多项结果中挑选一个作为主要发现。

历史680条开发数据的冻结七维参数同时给出各策略预算曲线，条件于同一个NNN父失败，反思更新核保持原值；没有重新拟合，也未采用已拒绝的阶段候选。纠正与删命题在该摘要下必须预测相同。比较各分支绝对概率、收益差及其预算变化，用于检查恢复条件下的适用性，不以总体Brier替代机制结论。

所有实际失败后的新反思进入完整标注队列。自动评分先核验原生成败、记忆链和动作，新的错误语义需全文标注后再报告。写回采用从共同起点出发的“失败且新反思含目标错误”联合事件；条件于失败的比例单独描述，避免把成功停止后的不同人群当作相同样本。

## 资源、停止与工件

资源为GPU2、3，各一个相同服务副本，缓存比例0.35；同任务全部条件留在同一副本，任务按固定索引奇偶分配。准备中先观察GPU2被占用，后续两次快照确认其已空闲后才启动本项目服务。GPU0、1不使用，其他程序不终止。

总额度120000个新增请求，包含四个副本检查；从本批最早服务启动起最多48小时。请求先预留、响应全部记账；超额、超时、未知响应或完整性失败即停止并保存日志，不自动重启或补发。自动收尾核验协议、动作统计及冻结评分，关闭额度，仅释放会话身份与创建时间匹配的本批服务。134个留出任务不调用，参数拟合为零。
