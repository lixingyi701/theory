# 原生反思计数与尝试阶段：一次有出口的校准比较

日期：2026-10-29。本轮接受外部审核指出的识别问题：最近1553条开发记录中，原生反思数等于尝试序号减一，范围为0至3。`1(n=1)`在这些数据上等价于第二轮指标。函数比较用于判断线性阶段限制是否造成预测折中，不能识别原生记忆的因果作用。研究中心仍为同一失败起点的纠正／删除收益及其持续时间。

## 比较、数据和边界

复用1553条开发记录、163任务、27场景和760条起始轨迹。原线性函数为`n/3`，新候选仅将同一列替换为`1(n=1)/3`；其他六列、任务三类截距、尺度1.5、先验、岭参数0.01与反思更新核保持不变。对齐n=1处的取值不保证整个设计矩阵具有相同惩罚效果。固定原系数时，最新276条分支的首轮历史和当前输入均相同，所以预测不变；任何改善都来自重新估计系数及不同阶段之间约束的变化。

原线性模型复用此前27个整场景留出系数和预测，不重跑。新候选27折加三个全数据初值，共30次CPU拟合，单进程、900秒总运行上限；无Agent调用，不触碰134留出。拟合目标沿用整任务混合似然。本轮不搜索第二种函数，不改任务潜类，也不根据结果调整阈值。

主要评价沿用固定起点、预定最多四次尝试的到达Brier风险。采用原预定的场景／任务／分支权重，不除以实际轨迹长度。只有主要改善大于场景配对标准误，且初始C/N与晚轮含错的条件Brier均不增加，才保留为阶段校准候选；否则关闭这一函数分支。无论结果如何，本轮不自动替换历史冻结基线，也不将预测改善解释为机制鉴定。

## 共享父记录与共同失败

46个父失败各产生三条件、两个种子的六个分支，共276条。建立显式父子索引，父失败在条件预测时仅更新任务后验一次。新分支不加入本轮拟合，作为已观察过的开发诊断，用相应留出场景模型转移预测。不能将六个子分支当成六次独立父失败，也不能将配对三条件当成六个独立种子。

每条件分别报告成功均值、逐条误差与两种子都失败／仅一次成功／两次成功的任务数。另给按实际均值构造的同概率独立参照，区分均值失配与共同失败过多。该参照用于描述，不是拟合后的新任务混合模型或残余依赖显著性检验。

## 恢复收益与下一项机制比较

同时整理已有100任务验证中的25场景恢复面板，报告保留、纠正最新错误、整条删除最新错误的1至4次成功曲线，以及三种配对收益曲线。使用全部150条既有轨迹、场景配对t95区间，自由度24；这是采集后的描述性整理，不更改原主要结果，也不据12个逐点区间挑选新显著结论。

下一项真实机制比较将回到具有明确目标错误的原生反思，在同一父失败、相同尝试编号下预先安排保留、纠正目标命题、删去目标命题、删除整条反思。这会使记忆条目数和内容在同一轮次内发生变化，打破自然序列的绑定。具体父记录、编辑范围、措辞与长度对照、精度和采集预算需在新请求前另行冻结。

不同失败历史若没有展示给Agent，且任务、环境、完整提示及随机请求机制相同，不能当作直接改变actor的干预；历史可用于预测者对任务的条件判断。改变尝试编号还会改变现有种子映射，不能把这类随机差异解释为历史效应。后续实验先操纵真正可见的记忆，不添加无作用的轮次标签对照。

若要进一步检验删除对信息退出时间的作用，应在相同初始可见文字下改变预定后续保留规则，以分开即时内容与后续移出时间。这是窗口机制诊断，须与原生FIFO的运输检验分开，不能把一句通用反思视为无作用空位。成功后停止导致后续失败样本组成变化；回写主要报告从共同起点出发的“失败且新反思含错”联合事件，并保留各分支预算内成功。

执行与独立复算源码分别为[比较脚本](../../scripts/compare_stage_calibration.py)和[复算脚本](../../scripts/analyze_stage_calibration.py)。本设计、源码和协议在拟合前公开冻结。
