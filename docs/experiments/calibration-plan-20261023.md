# 从配对分叉到跨恢复条件预测

当前执行链是：固定 Reflexion 与 Qwen 接口 → 独立场景 pilot → 同状态分叉 → 正式校准 → 冻结验证。本文明确后两步如何使用前两步的数据；pilot 用于确定观测和采样，正式验证使用新的基础任务。

## 先确定可以估计的机制

作者 Reflexion 只在失败尝试结束后写反思，下一次尝试重置环境与交互历史，并读取最近三条反思。因而第一版模型以尝试边界为时间单位，保留尝试内部的行为采用时间和成本。把每个动作都当成一次反思写入机会，会估计出与实际程序无关的参数。

| 量 | 定义与处理 |
|---|---|
| 目标错误的存储 | 对每条反思分别标注目标绑定／事实及其真值，保留来源和窗口位置 |
| 目标错误的暴露 | 按作者最近三条规则确定本次输入是否含目标错误；窗口移出是已知规则 |
| 信息冲突 | 记录当前公开任务、观察及其他记忆中是否存在相反证据 |
| 行为采用 | 依据明确的目标相关 thought 与动作标注；错误容器的普通搜索不自动计为采用 |
| 成功与新反思 | 成功由 native won 判定；失败后标注新反思是否重述、纠正或未涉及目标命题 |
| 预算与控制器 | 记录尝试序号、剩余尝试、已花费请求／tokens 和重复动作终止；基础设施中断单列 |

同一错误条目仍然可见、新反思未再提到它，是两个不同事件。目标错误的消失也可能伴随另一种错误，因此任务成功、指定错误动作、返工及竞争错误分别统计。对象位置事实与计划目的地绑定分别估计。

## 校准数据与模型

正式数据按基础任务分区，同一任务的全部恢复分支和种子留在一个分区；场景重叠另行检查。目标资格与替换规则先冻结，再查看分支结果，报告全部抽样任务中的合格比例。校准和验证都保留失败、未完成及不合格原因。

训练池清点发现，排除全部开发清单和示例后还剩 46 个房间，但加热任务只剩一个新房间，冷却任务没有剩余新房间。因而后续校准可以使用开发房间中的新基础任务，也可纳入明确标为校准用途的 pilot 数据；验证房间和任务继续独立保留。不能把“每一阶段都换全新房间”作为六类实验的统一采样要求。清点依据保存在 `repro/reflexion-20261023/sampling-capacity.json`。

现有 134 holdout 涉及四个房间，包含 21 个冷却和 23 个加热任务。使用它时，主要结论应针对这组固定 benchmark 任务的预测；同时报告按房间的结果。四个房间不足以精确估计更大房间总体的变异，新房间泛化需要额外测试场景。测试任务及其全部分支均不参与状态设计、拟合或模型选择。

第一版候选状态包括目标条目在三条窗口中的位置、其他正确目标提及、冲突证据、已有尝试数、任务类别与剩余预算。环境和活动历史在原生尝试边界的重置方式由程序确定。若同一候选状态下恢复路径仍提供稳定的预测信息，使用轨迹定位缺失变量，再在校准集内修订；最终测试前固定表示。

先比较最小的尝试级转移模型。只有在行为采用和反思回写均有事件覆盖时，才分解为“暴露 → 采用 → 尝试结果／反思更新”。行为采用属于将来事件，预测时对其积分，不能把事后采用标签直接当作已知输入。窗口推进与逐出用实际规则计算；数据估计的是采用、成功及命题回写等机制。

公平基线包含按任务类／尝试数的经验成功率、尝试级模型，以及使用相同起点信息的 logistic 或 hazard 模型。模型选择按基础任务分组交叉验证，记录参数数目和稀疏状态。采样量依据配对结果的任务间方差、目标误差范围和实际成本确定；四个 pilot 任务不能替代正式独立样本。

## 冻结与执行验证

首先考虑把“保留错误／定点纠正”用于机制校准，将“丢弃新增反思”作为未拟合的恢复条件。无反思的原生首尝试可以补充干净记忆状态的覆盖；是否足以覆盖丢弃后的控制器和预算，要用校准数据检查。需要补充状态时，在冻结前补采，不能在看到测试结果后补拟合。

验证前保存以下对象的 hash：任务分区、资格与注入规则、状态编码器、标注规则、拟合参数、预测脚本及评估脚本。先对新任务的起点产生预测并保存，再运行留出恢复条件。以一个和两个剩余尝试作为首轮预算条件，保持 actor 看不到预算；按真实调用另报成本。需要推广到调用预算时，再拟合带持续时间的事件过程。

主要结果为成功概率的 Brier、log loss、校准、配对恢复收益误差，以及首次目标行为采用和返工。区间按基础任务聚类，另报场景分布。状态覆盖不足、事件缺失或独立任务过少时，保留机制问题并补采对应数据；不把无法识别的转移概率填成零。

正式冻结工件在获得 pilot 的资格率与配对结果后生成。当前 134 holdout 尚未调用模型，其用途与场景统计解释需要在使用前固定。

执行证据见 [Reflexion 实测记录](reflexion-results-20261022.md)，主问题见[研究协议](../research/agent_error_recovery_model_and_protocol.md)。
