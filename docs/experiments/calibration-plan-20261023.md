# 从配对分叉到跨恢复条件预测

当前执行链是：固定 Reflexion 与 Qwen 接口 → 独立场景 pilot → 同状态分叉 → 正式校准 → 冻结验证。本文明确后两步如何使用前两步的数据；pilot 用于确定观测和采样，正式验证使用新的基础任务。

## 先确定可以估计的机制

作者 Reflexion 只在失败尝试结束后写反思，下一次尝试重置环境与交互历史，并读取最近三条反思。因而第一版模型以尝试边界为时间单位，保留尝试内部的行为采用时间和成本。把每个动作都当成一次反思写入机会，会估计出与实际程序无关的参数。

| 量 | 定义与处理 |
|---|---|
| 目标错误的存储 | 对每条反思分别标注目标绑定／事实及其真值，保留来源和窗口位置 |
| 目标错误的暴露 | 按作者最近三条规则确定本次输入是否含目标错误；窗口移出是已知规则 |
| 信息冲突 | 记录当前公开任务、观察及其他记忆中是否存在相反证据 |
| 行为采用 | 区分错误建议被尝试与实际执行：放置被拒绝时，物体可能仍在手里；结合 thought、命令与公开反馈标注，普通搜索不自动计为采用 |
| 成功与新反思 | 成功由 native won 判定；失败后标注新反思是否重述、纠正或未涉及目标命题 |
| 预算与控制器 | 记录尝试序号、剩余尝试、已花费请求／tokens 和重复动作终止；基础设施中断单列 |

同一错误条目仍然可见、新反思未再提到它，是两个不同事件。目标错误的消失也可能伴随另一种错误，因此任务成功、指定错误动作、返工及竞争错误分别统计。对象位置事实与计划目的地绑定分别估计。

动作格式也作为独立的竞争失败记录。配置审计用于验证实际模板、采样和命令翻译；动作审计统计观察句误作动作、未匹配的工具形式及合法形式下的无效果反馈。解析器只统一已验证的等义表示，语义修复属于另一个恢复条件。后续变更提示约束、工具契约或骨干模型时，保存新版本并重新完成开发检查，不能把改动前后的失败直接汇成同一转移机制。

操作前提开发诊断已出现目标事件：错误反思保留后的两次重试均先把杯子放入微波炉，再因未持有杯子而加热失败，两条新反思又重申了这一错误顺序。定点纠正分支 17 步成功，但仍尝试放入杯子；放置被拒绝，杯子继续留在手里，随后宏才成功。丢弃分支 22 步成功，没有尝试放置目标杯子。因而采用、执行生效和成功分开标注，设备状态及反馈如何阻止或放大错误也进入事件分析。该案例与后来完成的 24 个新加热／冷却任务分别汇总。

## 校准数据与模型

冻结接口后的首轮有 24 个新任务、8 条失败反思，其中 4 个目的地绑定合格。五条件配对分叉已全部完成，但错误分支没有出现指定错误目的地动作：三个任务仍有正确目的地放置，cloth 任务则被另一种物体错误阻断。目标句与当前任务的重复描述冲突，因此本轮提供了暴露与信息冲突证据，尚未覆盖采用转移。

下一实施单元先在开发池扩展由公开历史支持、且不被当前任务直接重述的观察事实、搜索覆盖和操作前提。先固定目标资格、证据核对和替换规则，再执行后续分支；记录整个抽样池的合格率与全部未采用结果。不同命题类型分别汇总，不因某个目标没有生效而事后删除。操作建议的语义修复与工具拼写翻译分别定义，避免把前提错误重新归入格式问题。

正式数据按基础任务分区，同一任务的全部恢复分支和种子留在一个分区；场景重叠另行检查。目标资格与替换规则先冻结，再查看分支结果，报告全部抽样任务中的合格比例。校准和验证都保留失败、未完成及不合格原因。

训练池清点发现，排除全部开发清单和示例后还剩 46 个房间，但加热任务只剩一个新房间，冷却任务没有剩余新房间。因而后续校准可以使用开发房间中的新基础任务，也可纳入明确标为校准用途的 pilot 数据；验证房间和任务继续独立保留。不能把“每一阶段都换全新房间”作为六类实验的统一采样要求。清点依据保存在 `repro/reflexion-20261023/sampling-capacity.json`。

现有 134 holdout 涉及四个房间，包含 21 个冷却和 23 个加热任务。使用它时，主要结论应针对这组固定 benchmark 任务的预测；同时报告按房间的结果。四个房间不足以精确估计更大房间总体的变异，新房间泛化需要额外测试场景。测试任务及其全部分支均不参与状态设计、拟合或模型选择。

第一版候选状态包括目标条目在三条窗口中的位置、其他正确目标提及、冲突证据、已有尝试数、任务类别与剩余预算。环境和活动历史在原生尝试边界的重置方式由程序确定。若同一候选状态下恢复路径仍提供稳定的预测信息，使用轨迹定位缺失变量，再在校准集内修订；最终测试前固定表示。

状态覆盖还包括条目之间的冲突：纯 E／纯 C 窗口可以拟合数量或位置的加性系数，但没有直接测量 E 与 C 共存的交互效应。当前 ECC／CCE 试验把这一组合外推作为开发检查。正式校准应预先安排部分混合窗口，例如 EC／CE，再留出其他组合或预算；新增状态参数要有对应数据支持。新反思未提及目标前提或表达含糊时，保留单独类别，不能并入 C。

先比较最小的尝试级转移模型。只有在行为采用和反思回写均有事件覆盖时，才分解为“暴露 → 采用 → 尝试结果／反思更新”。行为采用属于将来事件，预测时对其积分，不能把事后采用标签直接当作已知输入。窗口推进与逐出用实际规则计算；数据估计的是采用、成功及命题回写等机制。

尝试级分解还需保留“动作尝试 → 执行接受／拒绝 → 操作状态 → 后续结果”。放置被拒绝和放置已执行，会让同一条 heat 命令产生不同结果。预测时对这些未来过程积分；事后看到的手持状态和宏成功不能直接作为恢复起点的已知特征。

公平基线包含按任务类／尝试数的经验成功率、尝试级模型，以及使用相同起点信息的 logistic 或 hazard 模型。模型选择按基础任务分组交叉验证，记录参数数目和稀疏状态。采样量依据配对结果的任务间方差、目标误差范围和实际成本确定；四个 pilot 任务不能替代正式独立样本。

## 首轮受控状态开发试验

操作前提诊断提供了一个原生错误反思；新热处理清单又预先核对了三个合格目标。先在这四个已知开发任务上验证状态表示与冻结流程，再确定正式采样量。

记 E 为包含指定错误前提的原生反思，C 为只纠正该前提后的同一条反思。两者保留其他建议及竞争错误。按照作者三条窗口的读取方式，受控构造空窗口、E、EE、EEE、C、CC、CCC 七种校准状态；同一条目的重复是本轮主动干预，不作为自然产生的独立反思。已有空窗口、E、C 的真实第一次后续尝试在身份、种子和输入核对后复用，其余 16 个任务—状态单元重新执行。

结局固定为一次后续尝试内的 native won，最多 49 次作者决策，失败后仍运行原生反思更新器。比较平滑总体成功率、只计 E/C 数量的正则 logistic，以及保留三个窗口位置的正则 logistic。后两者在四个任务间留一交叉验证选择正则系数。28 个单元来自四个基础任务，不能按 28 个独立任务解释。

完成同质窗口后保存参数、编码器及 ECC、CCE 两种混合窗口的预测，再执行这八个新单元。二者条目多重集相同，仅错误位置不同，数量模型给出相同预测，位置模型可以给出不同预测。报告 Brier、log loss 和每个任务的顺序差异；预测冻结后不再拟合。

该试验研究已知任务上的新记忆组合，是单次成功概率模型的开发检查。正式研究还需新任务、自然回写事件、剩余尝试预算与多步转移预测。四个开发任务的结果用于筛选状态设计，不替代 134 个留出任务的验证。

混合窗口执行前另预注册一个任务难度诊断基线：每个任务使用七种同质状态的 Beta(1,1) 平滑平均成功率，对两种混合顺序给出同一个预测。它衡量已知任务难度本身的预测价值；新任务没有这些校准结果，不能直接使用这一基线。其注册、参数和预测单独保存，不改变主要三模型的选择与预测。

本阶段沿用当前 6000 次新增调用、三小时的总限额；校准新增调用上限 1400，混合窗口验证上限 800。源代码和协议先上传，再开始校准；参数和具体预测先上传，再执行混合窗口。

该轮现已完成：校准新增 581 次调用，验证新增 360 次；八个混合窗口全部失败，数量和位置模型均未优于总体均值。完整表格、轨迹与时间线见[首次冻结预测结果](state-prediction-20261023.md)。后续先补充混合冲突与独立任务覆盖，再冻结新任务和多步预测。

## 冻结与执行验证

首先考虑把“保留错误／定点纠正”用于机制校准，将“丢弃新增反思”作为未拟合的恢复条件。无反思的原生首尝试可以补充干净记忆状态的覆盖；是否足以覆盖丢弃后的控制器和预算，要用校准数据检查。需要补充状态时，在冻结前补采，不能在看到测试结果后补拟合。

丢弃发生在一个原生失败前缀之后，首尝试则包含全部被抽中的任务。即使二者都没有反思，任务难度的选择和尝试序号仍可能不同。覆盖检查必须考虑已有失败、控制器与剩余预算，不能直接把全体首尝试成功率当作失败后丢弃反思的重试成功率。

验证前保存以下对象的 hash：任务分区、资格与注入规则、状态编码器、标注规则、拟合参数、预测脚本及评估脚本。先对新任务的起点产生预测并保存，再运行留出恢复条件。以一个和两个剩余尝试作为首轮预算条件，保持 actor 看不到预算；按真实调用另报成本。需要推广到调用预算时，再拟合带持续时间的事件过程。

主要结果为成功概率的 Brier、log loss、校准、配对恢复收益误差，以及首次目标行为采用和返工。区间按基础任务聚类，另报场景分布。状态覆盖不足、事件缺失或独立任务过少时，保留机制问题并补采对应数据；不把无法识别的转移概率填成零。

正式冻结工件在获得 pilot 的资格率与配对结果后生成。当前 134 holdout 尚未调用模型，其用途与场景统计解释需要在使用前固定。
