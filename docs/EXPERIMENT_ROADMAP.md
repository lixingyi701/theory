# 2–4周实测路线

起点为2026-10-16。按依赖推进，日期是计划窗口，耗时取决于真实接口、模型能力与样本成本；不预先承诺结果。

| 窗口 | 主要工作 | 结束时应有的证据 | 需要据此决定什么 |
|---|---|---|---|
| 第1–2天 | Linux部署、数据manifest、10任务replay、24任务clean/sham | 真实审计报告、48episode结果、成本与格式统计 | 系统能否进入机制试验 |
| 第3–5天 | 注入与R0–R3、少数任务人工核对、配对pilot | 注入覆盖、污染可观测性、R1/R2差异与区间 | 修复残余能否被识别，状态摘要是否需改 |
| 第6–9天 | 校准任务、转移/恢复参数；实现依赖链工具环境 | 可估计参数、基础预测基线、生成器真值检查 | 哪些假设成立，年龄/暴露是否必要 |
| 第10–14天 | 冻结模型与留出长度/修复条件；核心simulation | 校准误差、固定参数外推、失配分析 | 最小论文主线是否已获证据 |
| 第15–21天 | 扩充独立任务/种子、公开split、14B复核 | 不确定性收敛、结果稳定性 | 样本是否足够，是否需要第二环境 |
| 第22–30天 | 必要时ScienceWorld、失败分析、最终图表与归档 | 适用边界、完整证据链 | 可支持的最终贡献与论文表述 |

前两周优先完成一个环境的机制与一个可控任务族的冻结预测。只有发现具体适用范围不足，才增加第二环境，不把有限时间用在全面部署多个Agent框架。

并行的理论工作：先完成状态/事件与清除条件；根据pilot修订可观测摘要；随后推导结构化残余风险与可组合条件。纯simulation可检验公式与失配，但实际LLM的留出预测必须单独运行。

预算按阶段释放：先测平均动作/调用/tokens，再估计下一矩阵总量。目标不是遍历所有组合；每个追加实验都对应一个尚未判别的机制或精度问题。
