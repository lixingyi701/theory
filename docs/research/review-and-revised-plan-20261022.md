## 2. 总体判断与发展潜力

CCFA 概念结论为 **pivot-with-rescue-route：保留科学问题，调整建模与验证路线**。发展潜力较高，关键是把“错误仍然存在”推进成“这些可观测残余在什么条件下能预测任务完成损失”。

对 CCF-C 目标，合理的投稿形态是机制分析与可靠性建模论文。一个公开环境、清楚的干预对象、有竞争力的预测对照、独立留出验证，能够构成有内容的研究包。是否适合具体会议仍取决于其征稿范围与最终结果。不能因为目标是 CCF-C，就把已知现象或标准概率公式包装为新理论。

当前最主要的问题是**理论中的 Agent 与正在运行的 Agent 不一致**：旧协议描述逐步写入的结构化记忆；当前 ReAct 没有独立记忆；候选 Reflexion 的反思则在尝试边界写入。仓库已在 10 月 22 日明确承认这一点，但新的正式模型和干预协议还没有落地。

## 3. 问题价值与贡献拆解

研究对象应限定为：冻结权重的语言模型 Agent，在可重置的工具环境里执行任务；恢复时重置环境和当前交互历史，却保留了一部分任务内反思；研究其中错误内容再次影响行动的概率，以及它对有限预算任务完成的作用。

问题的重要性来自恢复系统中的信息取舍：全部丢弃经验会失去有用知识，全部保留又可能带回错误。部署者需要知道保留什么信息会产生多少风险，而不仅是获得一个总体成功率。

建议拆成三个候选贡献：

1. **机制识别**：同一恢复状态、同一预算、相同非目标记忆下，估计目标错误残余对复发和完成的平均干预效应。
2. **事件驱动预测**：按真实 Agent 的行动、反思写入、重试三类事件建立模型；判断污染状态是否在进度、预算和任务难度之外提供预测信息。
3. **冻结参数验证**：在新的基础任务和未参与拟合的恢复条件上检验预测；长度外推作为更强、单独报告的后续目标。

已有 Python runner、日志、恢复审计是支撑上述贡献的基础设施。它们有复现价值，但不直接构成错误迭代理论。

## 4. 最近工作与创新边界

**经过这些比较，可保留的差异是一个组合问题：在有可验证工具目标的真实 Agent 中，使用干预识别的残余状态与事件转移，预测尚未拟合条件下的有限预算完成概率。这个差异是有依据的研究机会，不是已经证明的独占新颖性。**

## 5. 机制、假设与理论需要怎样修改

### C1｜高优先级：使时间粒度匹配真实 Agent

旧模型令每个动作都有 C→M 写回概率 β。但固定 [Reflexion main.py](https://github.com/noahshinn/reflexion/blob/218cf0ef1df84b05ce379dd4a8e47f17766733a0/alfworld_runs/main.py) 在一次 trial 后调用更新，[generate_reflections.py](https://github.com/noahshinn/reflexion/blob/218cf0ef1df84b05ce379dd4a8e47f17766733a0/alfworld_runs/generate_reflections.py) 为失败任务生成反思。一次尝试内记忆不持续写入。

**修改**：采用两层时钟 `k=尝试编号`、`t=尝试内决策编号`，另存工具动作数、实际 dispatch 数和 token 成本。尝试内使用行动核；失败后的反思事件使用写入核；重试边界使用环境与历史重置算子。β 仅在反思事件上估计。只有真实存在写入机会，才计入分母。

这可以写成事件驱动 Markov/半 Markov 模型，但模型名称本身没有新颖性。首先需要检验这个分解比简单结果预测器带来什么收益。

### C2｜高优先级：分开存储位置、暴露和行为采用

旧协议一处把 C 定义为包含当前记忆的策略输入，另一处又区分 C 与 M 污染。如果按整段 prompt 是否含错标记 c，那么 M 被读入 prompt 就自动使 c=1，M→C 会变成拼接程序制造的现象。

**修改**：定义存储层的 M、当前尝试的交互历史 C、由两者渲染的策略输入 P，分别标记 `m_stored`、`m_exposed`、`c_history`、`y_adopted`。实际复发要求新生成的行动参数或明确陈述采用了目标错误，不把复制到 prompt 算作复发。

Reflexion 完整历史通常只追加内容；若 c 表示“历史里出现过错误”，它不会因为后来不再犯错而回到 0。因此 γC 不能同时表示文本删除和行为纠正。将纠正/覆盖另标为当前效力或行为事件；清除历史发生在重试/恢复边界。源文本明确否定错误时，也不能仅凭关键词出现标为污染。

### C3｜高优先级：尝试内 M 不更新，会改变 R1/R2/R3 的可区分性

直接注入 M 后，只运行两步或六步再回滚，Reflexion 的 M 在这段期间通常没有变化。若 R2 恰好恢复被改的那一句、R3 又回到注入前完全相同的 M，那么 R2 与 R3 可能完全相同。此时没有“保留新知识与丢弃新知识”的比较。

**修改**：近期主实验使用一次自然失败后生成的反思作为父记忆，在下一次尝试开始前构造保留、定点纠正与丢弃新增反思的分支。只有实际经历过新增记忆的边界，R3 才能识别额外经验的代价。中途回滚试验保留为后续扩展，明确其外部恢复调度是研究干预。

### C4｜高优先级：标准数学工具不能承担全部理论贡献

协议 §7 的完整状态恢复等价、竞争风险求和、有限步耦合误差界，在各自条件下是合理的基础工具。文档已经恰当地承认它们是标准工具，T1–T3 仍未完成。不能以这些锚点加一张成功率图声称建立了普适错误迭代理论。

**修改**：优先完成一个可检验的事件驱动模型和明确适用条件。若继续追求理论论文，需进一步推导利用载体残余、暴露和剩余工作结构的结果，而不是仅将误差界写成 `δ₀+Bε`。若最终贡献主要是干预证据与可靠预测，应按机制/建模论文组织，不强行强调新概率理论。

### C5｜中优先级：两位污染摘要不一定充分

相同 `(c,m)` 可以对应完全不同的目标相关性、错值、记忆可见位置、纠正信息以及剩余任务难度。四状态核能够拟合，不等于其具备稳定外推性。

**修改**：先保留最少的任务阶段、目标相关性、预算、记忆暴露和事件类别。比较四状态模型、按真实顺序分解的事件模型与同信息量的直接预测器。只增加能够改善独立开发预测的特征。年龄作为可选项；不要预设“越老越危险”。

### C6｜中优先级：创新表述需要更新

原综述仅五篇，遗漏依赖引导修复和近期暴露控制工作。建议明确新增近邻，并将“错误潜伏、回滚保留记忆、选择性删除”的角色改为实验前提和已有机制。将论文的新贡献押在干预估计、过程到目标结果的连接、固定参数验证上。

## 6. 值得保留的设计

1. **同一父轨迹分支**：降低不同失败历史造成的混杂，是研究恢复后效应的正确基础。
2. **R1/R2 的匹配思想**：环境、当前历史和预算匹配，只改变目标污染，比单纯比较回滚与不回滚更能解释机制。
3. **区分 H、t、B**：规定任务工作量、实际运行步数和预算分开，避免把失败造成的长轨迹解释为长度导致失败。
4. **原生 won、独立 evaluator、完整分母**：任务结果不依靠模型自评；中断与缺失不伪装成科学负结果。
5. **冻结后预测与强基线**：协议已提出 Brier/log-loss 与同特征 logistic/hazard 对照，方向正确，应保留。

历史证据见 [10 月 19 日结果](https://github.com/lixingyi701/theory/blob/5b58de8e1cb8c32a3b6d0de5b4373bb217cba917/docs/experiments/results-20261019.md)，当前证据见 [10 月 22 日结果](https://github.com/lixingyi701/theory/blob/5b58de8e1cb8c32a3b6d0de5b4373bb217cba917/docs/experiments/results-20261022.md)。不同 Agent 的 0、6/12、7/12 不能组成受控“提升曲线”。

本次重新汇总当前 12 条记录，得到 7 成功、406 次 dispatch、903,529 输入 tokens、5,547 输出 tokens，与 summary 一致；三份任务 manifest 的内容摘要校验通过。重新运行 19 项现有离线测试后全部通过。Windows 初次 checkout 的 CRLF 转换导致 3 项作者源码 hash 测试失败；在本次审查副本恢复 Git 中原始文件字节后通过，没有改写算法。这是可通过 `.gitattributes` 固定 vendor 字节的可移植性问题，不是否定 Linux 上的历史结果。

### A1｜高优先级：现有 resume 不能直接等同于研究用 fork

`reference.py` 的恢复通过重新执行作者函数、复用持久响应并检查已提交环境前缀完成。这适合断线续跑。注入与恢复分支需要不同记忆、不同后缀响应，同时保留同一父轨迹。不能把新分支写入原运行目录，或在干预后继续复用原未来响应。

建议新增独立的 `parent_id / fork_event / branch_id`、不可变父检查点、分支专有 journal；父前缀可以读缓存，分叉点后必须重新调用模型。缓存键包含实际输入与方法版本。R1/R2 共用父轨迹、预定随机流与预算；随机流相同不保证不同提示有相同输出。

### A2｜高优先级：当前服务不能直接承载完整 Reflexion

`serve_reference.py` 固定 raw completion、temperature=0、100 tokens、newline stop；其校验会拒绝其他设置。官方 Reflexion actor 有短输出升温重试，反思调用有单独提示与输出需求。不能把当前服务接上去就称作者 Reflexion 已复现。

需记录完整作者依赖、示例、utils、actor 与 reflector 的调用契约，冻结 8B 替换方式；为反思与重试设计有明确身份的新服务 profile。短输出重试按真实 dispatch 计费，不与网络不确定请求混淆。核对作者 `done` 成功判定与固定环境 `won`；若有非成功 done，修正并披露适配，不继承错误标签。

### A3｜高优先级：预算有三个时钟

49 轮是作者决策循环的上限，包含 think；不是 49 次有效工具动作。Reflexion 一轮还可能因短输出产生多次 dispatch。保存决策轮、环境调用（含 think）、实际任务动作和模型请求数，另存 tokens。尝试成功与整个预算内成功分别统计。一次尝试失败后若仍可重试，不应进入全局不可逆失败吸收态。

### A4｜高优先级：134 个任务只有 4 个场景

本次从 [holdout134.json](https://github.com/lixingyi701/theory/blob/5b58de8e1cb8c32a3b6d0de5b4373bb217cba917/repro/baseline-20261019/holdout134.json) 重新计数：FloorPlan10 为 77 个，FloorPlan308 为 27 个，FloorPlan424 为 19 个，FloorPlan219 为 11 个。134 是任务数，场景只有 4 个。

维持封存集合，按任务配对分析时说明结论条件于这些场景；同时报告逐场景效果与等场景权重敏感性。只有 4 个场景时，普通场景 bootstrap 不能支持可靠的广泛场景总体区间。更广泛泛化需要另找更多独立场景或任务域。同一场景不能跨正式拟合/测试；额外 seeds 不补充场景多样性。

### A5｜中优先级：greedy 解码下“多 seed”不自动增加独立样本

当前 temperature=0。仅改请求 seed 可能得到完全相同的轨迹；数值非确定性也不是可控的科学采样。优先增加独立基础任务。若为了估计随机策略概率启用采样，应在开发阶段统一冻结配置并重建基线；不要把同一 greedy 轨迹的重复执行当成独立样本。

## 10. 修订后的主实验方案

### 10.1 系统组成

主载体：固定作者 **Reflexion 的 actor＋反思更新＋任务内 memory**，底层使用已固定的 Qwen3-8B 权重。环境：ALFWorld TextWorld。研究组件：外部记录器、受控错误编辑器、分支恢复器、独立 evaluator。ReAct 保留作无独立反思记忆的能力参照。

这里的“错误迭代更新”发生在历史与记忆层；LLM 权重不更新。观测真值只用于注入资格、结果标注及 oracle 干预；不会作为常规工具观测泄漏给 Agent。

```text
公开任务与观察 → Reflexion actor → 工具行动 → ALFWorld
                    ↑                         ↓
                 策略输入 ← 当前尝试历史 ← 公开反馈
                    ↑
              最近的反思记忆
                    ↑
        失败后的反思更新（尝试边界）

外部实验器：固定父状态 → 编辑目标反思 → 构造恢复分支 → 记录结果
独立评估器：核对真值、复发、预算与 won
```

### 10.2 近期最小实验：在重试边界识别记忆效应

先用原生 Reflexion 产生一次失败及其新反思，保存任务、环境初始状态、旧记忆、新反思、调用成本和完整父轨迹。只有反思包含能够独立核验、且下一次尝试可能用到的事实或明确操作前提时，才满足注入资格。反思是策略文本，不能假设它一定含有旧结构化 memory 的物体位置字段。

错误编辑只替换一个已核验的事实命题，保持其他反思内容与语气一致。例如父轨迹确实观察到苹果在 A，将新增反思中的 A 替换成场景内存在的 B。不要同时加入“必须相信”等强制指令。错误值不能通过一次预跑挑选最能导致失败的版本。

若天然可编辑事实稀少，报告资格覆盖并暂停该注入定义；不要强迫 reflector 改成事实抽取器还声称算法未变。可在开发阶段改选反思中可核验的动作前提错误，明确任务范围。

所有主比较分支从同一个环境重置状态和干净的当前尝试历史开始，给相同剩余预算。条件如下：

| 条件 | 记忆处理 | 目的 |
|---|---|---|
| Clean | 保留原生、未编辑的新反思 | 原生学习的参照 |
| Sham | 对相同目标执行等内容替换，输出完全相同 | 测量干预器本身是否改变输入 |
| R1 保留错误 | 新反思中的一个命题被改错，其余保留 | 残余污染处理组 |
| R2 定点纠正 | 在 R1 上仅将该命题还原为父轨迹已支持的内容 | 隔离目标内容的效应；oracle 机制参照 |
| R3 恢复旧记忆 | 移除本次新增反思，恢复该次反思生成前的 M | 衡量同时丢弃新知识的代价 |

这个边界实验中 R2 可能与 Clean 输入完全相同。这是有用的一致性检查，可以复用其参照身份，不应为了凑臂数重复计成新的独立证据。R3 也可能在某些任务与 R2 等价，应记录实际内容差异。

这一步识别的是“给定恢复后残余存在时”的内容效应，不估计自然错误产生率，也不估计真实修复器留下错误的概率 q。要连接不完全恢复与迭代更新，下一阶段必须让被污染记忆经历真实执行、失败反思及预定恢复，再测量其留存、被覆盖和派生写入；另行估计 q 与反思事件核。不能仅靠边界上手工放入错误就宣称真实修复器存在同样残留。

**R0 不恢复留给中途恢复扩展**：父尝试已经终止时，不应强行让它继续。边界实验可保留父尝试失败作为历史事实，但不能拿它与重新获得预算的分支解释纯记忆效应。

如果随后实施原四臂延迟恢复，则从同一尚未终止的污染父轨迹分叉：R0 保持原状态，R1/R2 匹配环境与历史回滚，R3 恢复完整检查点。中途 fork 必须恢复作者函数内历史、重复动作检测、调用序号、记忆渲染缓存和预算。R0 只参与完整策略结果，R1/R2 才是纯残余比较。

### 10.3 避免 oracle 清理偷偷增加知识

纠正内容必须来自干预前已经有的公开证据或配对原生反思，不能将 Agent 从未观察到的环境真值直接填入 R2 再归因为“清理的收益”。若只能用未知真值纠正，则它测量的是清理加额外信息，必须另标。

优先采取“原生正确命题→单点改错→原位还原”的设计，保证非目标内容相同。清除已经传播的派生反思属于下一阶段；只处理有可验证依赖的后果，未知部分标记 unknown。动作恰好指向错误容器不一定证明依赖该错误，需结合目标命题与配对对照报告，避免个体轨迹的过度因果归因。

### 10.4 评价对象与分析

主机制量采用：

`Δsucc = P(预算内成功 | R2) − P(预算内成功 | R1)`。

同时测首次行为复发的累积发生率、首次复发时间、目标错误被新生成反思继承的比例、无效/返工动作、tokens。将“memory 里有错误”“prompt 里展示错误”“行为采用错误”“最终任务失败”分别统计。

首次复发后的轨迹继续运行；不能把复发直接判为全任务失败。成功终止、明确不可继续终止与到预算未完成分开；infra 失败另计缺失。处理首次复发的竞争事件，不把成功退出的轨迹当作普通独立删失。

配对单位为基础任务及其父轨迹；分支和 seeds 嵌套其中。同任务多个注入点不增加独立任务数。预先给出总任务→自然失败→有反思→合格事实→完成分叉的样本流图。主效应条件于合格集合；同时报告全开发集原生完成率，防止选择性解释。

反思只在失败后发生，因此写入核条件于反思事件。成功分支没有下一条反思，不能把它当成“写入失败”，也不能只比较各臂失败者就宣称得到无条件的写回因果效应；事件是否发生本身由任务结果核建模。

在有足够场景的开发/校准集合中按场景分组划分；统计区间根据推断目标采用层级或任务 cluster 方法。134 unseen 的结论限定于其四个固定场景，单独报告场景异质性。

### 10.5 预测模型与基线

保留四类主要预测器：

| 预测器 | 输入与结构 | 关键比较 |
|---|---|---|
| M0 简单条件基线 | 任务阶段、预算、任务类型；可加简单几何模型作诊断 | 避免仅击败一个过弱的 p^H 对手 |
| M1 不区分载体的过程模型 | 相同任务与预算信息，粗错误/进度状态 | 分离 C/M 是否有额外信息 |
| M2 事件驱动残余模型 | M1 信息＋独立的 memory/history 标注、暴露与反思事件 | 主要机制建模对象 |
| M4 直接预测器 | 与 M2 相同的预测起点信息；正则化 logistic 或离散 hazard | 判断过程分解是否优于直接拟合结果 |

M3 年龄/暴露扩展暂列可选消融。M2 若使用 evaluator 真值，M4 也获得相同信息；两者均标为诊断性预测器。若追求部署能力，再使用只含 Agent 可见信息的第二组模型，不能混报。

以 Brier score 为预设主预测指标，log-loss、校准曲线、分条件误差为辅助。用基础任务配对差评估模型；在开发集选复杂度和概率平滑，测试集上不重新拟合。预测未来完成时，不能输入未来实际 rollout 长度、未来污染标签或未来暴露次数。

### 10.6 长度外推保留，但改变实施顺序

先验证固定参数能预测新的基础任务和未拟合恢复条件，再做 Dependency-Workflow。原 H=4/8/16 拟合、32/64 测试可以保留为目标矩阵，实际冻结前先检查预算与容量。

**直接冲突**：当前作者循环上限 49 决策，H=64 至少需要 64 次逐项提交，还没有计算读取操作。若原样搬用当前循环，长任务会因预算必然失败。需为受控任务族明确冻结随外生工作量增长的决策预算，例如按程序参考调用数 Lref 的比例；所有模型和条件使用同样规则。这是新任务协议，不能冒称不变的 ALFWorld 作者基线。

同时，全历史 prompt 会随 H 增长，32768 上下文可能成为另一种硬边界。先根据生成器和固定提示进行 token 容量检查，记录实际耗尽；不在测试中临时扩大窗口或裁切历史。旧方案的 16 条 FIFO 假设也应替换为真实 Reflexion 的历史与最近三条反思可见规则。

生成器只定义任务依赖、工具和 oracle，不按候选 Markov 核制造错误。真实 LLM 的长程预测与按已知核生成的 simulation 分开。短长任务的母实例不能跨分区；首次注入位置按预定规则匹配相对进度与剩余工作。

## 12. 哪些结果会改变判断

| 观察 | 科学解释与下一决定 |
|---|---|
| R1/R2 有清楚的复发差异，但完成率差异不清楚 | 支持目标错误影响行为；尚不支持任务失败模型，检查预算与后续纠正 |
| R2 比 R1 好，但 M2 不优于同特征 M4 | 清理效应成立，过程模型的额外贡献不足；不要以更复杂参数掩盖 |
| 同类短任务有效，固定参数长任务失准 | 报告外推边界；检查上下文、状态覆盖和任务机制改变，不重拟合后仍称外推 |
| 没有差异且区间很宽 | 结论不确定，增加独立基础任务或提高标注可观测性 |
| 能排除预设的有意义差异 | 当前系统对该类残余可能鲁棒；保留有价值的边界结果，停止重复同矩阵寻找显著性 |
| 跨条件预测有效、校准稳定、优于公平强基线 | 具备机制＋预测论文的核心证据；再按具体投稿目标组织贡献 |

近期最关键的三个答案是：原生反思中是否有足够可核验的目标；匹配分支是否产生可测的行为/结果差异；加入残余状态是否改善独立预测。先回答这三个问题，再扩大理论与实验范围。

## 13. 给项目的简单描述

**一句话版本：**

> 我们研究一个会反思、会重试的 AI Agent：它重来时虽然把环境和当前对话恢复了，但保留下来的错误经验是否会让它再次犯错，以及能否据此预测它在剩余预算内完成任务的概率。

**按实际流程描述：**

> 先用公开的 Reflexion Agent 程序接上固定的 Qwen3-8B 大模型，让它在 ALFWorld 中完成任务。任务失败后，Agent 会生成一段反思并留给下一次尝试。我们在这段反思中，将一个已经核实的事实改错，然后把环境和本次交互历史恢复到相同起点，分别保留错误反思、只纠正这一处错误、或者丢弃新增反思，让 Agent 在相同预算下继续。记录错误何时再次进入行动、造成多少返工、任务最终是否成功。最后用短程实验估计这些过程，在新的任务与恢复条件上预测结果；再用可控工作流检验长度外推。要验证的假设是：恢复后的可靠性取决于错误残余、记忆暴露与更新事件，以及剩余工作和预算，这些因素在明确条件下能够支持比简单错误率更准确的预测。

其中“能够支持更准确的预测”仍是待检验假设。完成这一验证，才是项目从可运行 Agent 走向研究贡献的关键一步。

## 14. 后续决策：保留问题，调整核心贡献

### 14.1 推荐与备选

用户补充：Agent 仍处初步构造阶段，可调整设计；确认路线后可上传本分析。当前建议为**中等幅度调整研究贡献，保留已有环境与执行基础设施**。不要为追求表面差异更换模型名字、增加记忆模块或扩大状态矩阵。

| 路线 | 核心操作与研究问题 | 判断 |
|---|---|---|
| A：沿原方案增加实验 | refine：继续证明残余错误导致复发，再拟合成功率 | 工程最省，但与多篇近邻重叠明显；单独作为贡献偏弱 |
| B：恢复状态的跨条件预测 | instrument：通过匹配分叉，检验恢复后状态是否足以预测复发及有限预算完成率，并预测未拟合恢复条件的收益 | **推荐**；保留原主问题，把贡献放在可证伪的状态表示、干预识别与迁移证据上 |
| C：更新导致的再污染与修复顺序 | invert：已清理的记忆是否被旧轨迹在下一次反思中重新写坏；改变写入与清理顺序能否阻断 | 可作 B 的机制扩展；只发现“最后清理更干净”过于直接，不能独立支撑新颖性 |
| D：设计预算自适应修复策略 | combine：估计污染风险、信息保留价值与恢复成本，再选保留、纠正或重置 | 当前暂缓；与 RIR、依赖回滚修复等相邻，诊断器与策略评测增加成本，容易把项目扩成另一个方法论文 |

建议暂定题目：**反思式 Agent 恢复后的可靠性：从残余状态到跨恢复条件预测**。贡献类型为机制与预测研究；不预设提出最优恢复算法，也不预设所有 Agent 共享同一组参数。

### 14.2 新增近邻改变了什么

本节补查日期为 2026-10-22；以下定位以所链接版本为准，预印本不等于已录用论文。

- **CCRM** 已讨论跨尝试污染与预算下成功率。因此，“重试并不独立”“污染使重试变差”“写出预算公式”均不能直接作为新贡献。其 §2 使用尝试级二元污染与固定成功概率；§7.2 从已给定的 pass@1、pass@3 反解参数，不能把该拟合精度当作独立迁移验证。我们的机会是显式干预恢复、跟踪真实后续轨迹、冻结参数后预测新条件，而非重述它的叙事。[原文](https://arxiv.org/html/2605.08563v1)
- **When Errors Become Memories** 已提供传播路径干预、潜伏残余及联合恢复证据。我们需进一步研究交互任务中的复发、返工、预算完成概率，不能只更换记忆载体。[原文](https://arxiv.org/html/2608.30198v1)
- **Dependency-Guided Rollback Repair** 已研究源错误、传播后状态、良性信息保留及修复后复发。“删掉错误仍可能复发”也不能单独宣称新发现。[原文](https://arxiv.org/html/2608.10502v1)
- **RIR** 已联合考虑回滚与保留反思；恢复时保留信息的利弊属于已有研究问题。**TraceToChain** 已用吸收链分析可靠性和时间分布，因此数学形式本身不构成差异。[RIR](https://arxiv.org/html/2609.18304v3)，[TraceToChain](https://arxiv.org/html/2604.24579v1)

补查的 MERIT 与 Invalidation Contracts 分别涉及跨任务修复经验复用、缓存恢复建议的失效；它们进一步说明“选择性保留正确经验”较拥挤。此两项本轮仅核对摘要，不据此断言其全文没有我们的机制。[MERIT](https://arxiv.org/abs/2608.05906)，[Invalidation Contracts](https://arxiv.org/abs/2609.00243)

**新颖性状态：已检索、存在明显重叠，但仍有可验证的差异空间；尚不能声称首次提出。** 新颖性需要体现为同一组校准参数对干预后结果的有效预测，以及简单近邻模型无法解释的可重复偏差。仅做随机训练/测试划分，或为每种恢复方式重拟合一次，都不足以支持这个定位。

### 14.3 核心假设必须比“有错误所以失败”更强

研究对象保持为固定模型与固定 Agent 协议。候选恢复后状态包括：环境与进度、当前交互中目标错误是否仍被采用、持久记忆中的错误及有证据支持的有效信息、下一类事件、剩余预算。具体变量先做可观测性审计，不把所有因素直接组合成稀疏大矩阵。

**H1：恢复历史能否被状态概括。** 在同一任务、环境与预算下，控制上述候选状态后，结果分布是否仍明显依赖“通过哪种恢复方式到达这里”。若仍依赖，则当前状态表示缺少信息；应报告状态不充分，不能给每个恢复臂另加自由参数后声称可组合。

**H2：事件机制能否迁移。** 在校准集识别记忆暴露、行为采用和尝试结束后的反思写入过程；冻结参数后，预测未参与拟合的恢复组合或预算条件的复发曲线和完成率。没有经过校准覆盖的状态或新型修复算子不纳入保证。

**H3：预测是否有额外价值。** 比较同样可用信息的 CCRM 风格尝试模型、经验成功率、灵活的 logistic/hazard 模型和事件过程模型。只有事件模型在独立数据上具有预测、校准或迁移优势，才支持其额外结构；更复杂不等于更好。

这里的“状态充分”是待检验的建模假设。实际数据只能在所测条件中支持其近似成立；未检出差异不能直接证明等价，应报告预先定义容差下的区间。离线标签可能来自 oracle，因此第一阶段结论是诊断性科学解释，不自动等于可部署在线预测器。

### 14.4 Agent 现在怎样调整

保留 ALFWorld、固定 Qwen3-8B、现有运行 journal、环境恢复与输入审计；沿用完整作者 Reflexion 接入方向。作者 ReAct 留作已验证执行参照，当前 ReAct 结果不能视为有独立反思记忆的验证。

增加四项研究能力：

1. **精确分叉**：同一任务前缀产生配对分支，明确 E、交互历史、持久记忆、控制器和预算；未来请求各自记录，恢复不返还已经花费的预算。
2. **事件日志**：分别记录 memory-visible、actor-action、trial-end、reflection-write、restore。反思只在原生触发点发生；不为凑齐四状态转移而改成每一步更新。
3. **命题级干预与审计**：保留注入目标、原事实来源、改动位置、是否真正暴露、是否进入行为及后续反思。出现相同错误不自动证明由注入导致；保留无注入对照，并区分来源支持与语义相同。
4. **策略外预测器**：先只读取校准与日志作预测，不反馈给 actor。避免“为了符合理论而改 Agent”与被验证系统相互影响。

良性信息的损失必须被记录：全部清空可能同时去掉正确经验。纠正分支只恢复已在共享前缀中验证的目标事实，不告知新的任务答案。若有预算优化需求，另行区分恢复前总预算与恢复后匹配预算，两种估计对象不能混称。

### 14.5 最值得先做的判别实验

先完成作者 Reflexion 的能力和 sham 检查，再开展一个小而完整的反思边界分叉实验：从自然产生且有可核验事实的反思中选一个目标，改变该事实；环境、当前历史和剩余预算恢复到相同条件。比较保留错误反思、仅恢复该目标原始事实、丢弃本次新增反思，同时保留未改动原反思与 sham。

先测三个层次：目标错误是否重新进入行动；随后反思是否继续保存或生成相关错误；有限预算内是否成功及付出多少返工。报告全部注入资格、跳过、提前成功和基础设施失败；反思写入只对原生发生该事件的轨迹定义，不能把无反思的成功任务当作“写入概率为零”的等价样本。

**第二步才测试 B 的核心差异**：校准与评估按基础任务分开；在校准内识别单一事件或恢复组件，留出一个预先指定、状态有覆盖的组合恢复条件及新的预算。模型冻结后预测其结果，再运行相应 LLM 分支检验。不得通过测试条件的结果反调状态、参数或阈值。预算外推采用预算无关的固定 actor 协议；若 actor 能看到预算并改变决策，需把它作为另一种策略条件建模。

未拟合条件的收益以配对差值评估，例如“纠正 vs 保留”的完成率增益及其预测误差；同时报告 Brier、log loss、校准和复发时间分布。基础任务为主要独立单位，不能把大量分叉、动作或 seed 当作独立任务扩张显著性。

**再污染扩展的进入条件**：真实轨迹中存在可审计的受污染反思输入，且清除指定记忆后，下一次原生更新仍可能从这些输入再写出目标错误。先对相同前缀执行局部更新实验，比较反思前清理输入、反思后纠正输出与相应 sham；再做在线后果。所有条件需要匹配可用事实和清理权限。“更新前后次序不同”不能与额外正确知识、额外调用或不同修复器能力混在一起。如果只能靠额外写入人为假错误得到该现象，就不把它作为原生机制贡献。

样本量由 pilot 的任务间方差、目标效应与可用预算确定。已有 dev12 用于工程诊断；正式确认性结论不能继续在该集合上调参。长任务外推保留为后续增强项，先完成跨恢复条件验证；沿用第 10 节的可达预算、上下文和任务分区约束。

### 14.6 继续、收缩与停止条件

- 若残余影响明确，且冻结的过程模型在留出干预上优于公平简单模型：支持继续机制与预测论文。
- 若清理有效，但简单模型已经同样准确：不支持扩大理论；可将项目收缩为有复现协议的诊断研究，但需新的实质发现，不能保证达到投稿要求。
- 若状态相同但恢复历史仍有稳定预测力：报告缺失状态或非平稳性；只做有证据的最小模型扩展，不无限堆叠状态。
- 若真实 Reflexion 几乎没有合格目标或不采用目标错误：改变错误类型或选择更适合该问题的公开 Agent，并清楚限定研究对象；不为了显著性偷偷更改原生协议。
- 若只能在手工生成、按模型设定制造错误的任务上成立：作为模型计算验证，不作为真实 Agent 的机制证据。

该路线对 CCF-C 目标具有可执行性，但“CCF-C”覆盖不同学科和审稿要求；尚无具体 venue，不能给出录用保证。新增文献使原有评分不宜被解释为对原样推进的背书，本轮不以新分数代替判别实验。

### 14.7 项目描述与路线确认

> 先把公开 Reflexion 程序接到固定大模型上，构成会执行、失败后会反思并重试的 Agent。我们在它真实生成的反思中改错一个有证据的事实，然后从同一个任务状态分叉：分别保留错误、只纠正该事实、或丢弃新增反思。在相同剩余预算下，观察错误如何再次进入动作、是否被后续反思继续保留，以及任务能否完成。用一部分任务估计这些事件的规律，冻结模型后，预测新任务和未用于拟合的恢复组合的结果。我们要检验的是：恢复后的哪些状态足以解释后续可靠性，以及这些机制能否提前预测恢复的收益。

用户于 2026-10-22 确认采用路线 B，C 按进入条件扩展。随后将研究分支整合回 main，由当前研究协议和实验路线图维护后续工作。
