## 1. 本轮决策与论文要回答的问题

**主问题：恢复了环境和活动上下文以后，保留下来的错误记忆如何再次影响行动与任务完成？能否从短程干预数据估计这一过程，并在固定参数下预测更长任务和留出的修复条件？**

本研究首先定位为机制与预测研究。主要实验比较不同可靠性模型的预测，不以提高 benchmark 排名为首要目标。若模型最终导出有用的恢复策略，再增加固定预算下的策略比较。

本轮固定的组合：

| 层次 | 选定系统或任务 | 职责 |
|---|---|---|
| Agent | 自建轻量 ReAct 式执行器，加显式任务内记忆与可恢复状态 | 让上下文、记忆、环境边界可记录、可干预 |
| 主 LLM | `Qwen/Qwen3-8B`，冻结权重，non-thinking 模式 | 首轮可复现、无训练的机制实验 |
| 第二 LLM | `Qwen/Qwen3-14B`，待首轮机制可识别后运行 | 检验结论是否依赖单一模型；两者同家族，不能称跨模型家族验证 |
| 主公开 benchmark | ALFWorld 的 TextWorld 后端 | 真实 LLM 的工具交互、目标完成与错误复发 |
| 长度控制任务 | 本研究拟建的依赖链工具任务族，暂称 Dependency-Workflow | 精确控制规定工作量、错误暴露及恢复边界；不是现成公开 benchmark |
| 后续外部验证 | ScienceWorld | 在另一类状态转移和科学任务上复核；不纳入第一轮工程实现 |

研究次序：一页论证与最小模型 → ALFWorld 接口与机制 pilot → 修订状态摘要 → 理论与 simulation → 冻结后的长度及修复条件验证。

## 2. 贡献、证据与否定条件

| 候选贡献 | 核心主张 | 必要证据 | 若结果不支持，如何调整 |
|---|---|---|---|
| C1 修复边界 | 同样恢复环境和上下文，保留的错误记忆可能产生额外后续风险 | 配对比较“保留记忆”与“语义清理目标错误”，以及完整重置边界 | 若差异区间宽，增加精度；若可排除有意义差异，则缩小到其他载体/任务，不能继续声称该环境存在显著残余风险 |
| C2 过程到结果 | 污染在载体间的转移与重用可改善任务结果预测 | 逐步状态观测、复发时间、成功/超时；优于无污染状态的强预测基线 | 若只能解释复发，不能预测任务完成，主张收窄为复发模型 |
| C3 外推 | 局部转移与恢复参数在限定任务族内具有可组合性 | 只用短长度拟合；锁定参数预测长长度及未拟合的恢复组合 | 若需每种长度重拟合，放弃“跨长度预测”的贡献表述，定位为条件描述模型 |
| 可选 C4 年龄 | 在污染、任务阶段、暴露已控制后，年龄仍有额外信息 | 留出预测增益及年龄/暴露的独立操纵 | 无增益就删除年龄项；C1–C3不依赖它成立 |

**主要竞争解释**：残余只是执行预算损耗的替代指标；错误年龄只是读取次数的替代指标；高难度任务同时造成污染和失败；清理记忆同时删除了有用信息；环境重放不一致制造了“残余”。实验要逐一隔离这些具体解释。

## 3. Agent 系统：明确哪些是已有方法，哪些是我们的实现

### 3.1 与 ReAct 的关系

采用“观察→简短计划/行动→工具反馈”的 ReAct 式单 Agent。[S1] 官方 ReAct 的 ALFWorld notebook 使用旧模型 API、两条示例和逐步累积的文本历史；本研究沿用交互范式，新增显式记忆及实验 hook。因此应称 **ReAct 式可观测 Agent**，不能把它的分数称为原论文 ReAct 的复现结果。

第一轮不引入多 Agent 协商、训练、向量数据库或大型工作流框架；这些会增加需要估计的状态与随机性。执行器使用普通 Python，环境通过独立适配器接入，LLM 通过固定本地推理端点调用。

### 3.2 每轮状态与调用顺序

完整可恢复状态记为

\[
W_t=(E_t,C_t,M_t,J_t,R_t,B_t).
\]

- \(E_t\)：环境真实状态及环境 RNG/内部计数；不直接提供给策略。
- \(C_t\)：策略可见的活动上下文，包括任务、最近交互、计划和当前工具反馈。
- \(M_t\)：本任务内的持久记忆；跨任务清空，避免未控制的经验积累。
- \(J_t\)：任务控制器状态、已完成子目标及尚未兑现的动作；策略能看到的部分单独规定。
- \(R_t\)：其他影响未来的运行状态，包括工具缓存、调用序号及随机流配置。
- \(B_t\)：剩余预算；回滚后不退还已经花掉的调用。

每轮执行：从最近观察更新记忆 → 构造策略输入 → 生成一个行动 → 环境执行 → 记录完整反馈与终止信息。记忆更新与行动生成分为两次调用，使用同一冻结模型但独立随机流，便于归因和记录成本。

拟定配置：

| 项目 | v0.1 配置 |
|---|---|
| LLM | Qwen3-8B，revision `b968826d9c46dd6066d109eabc6255188de91218`；tokenizer与chat template同revision |
| 思考模式 | `enable_thinking=false`；策略仍可输出一段简短 plan，不使用额外隐藏思考回合 |
| 采样 | temperature=0.7，top_p=0.8，top_k=20，min_p=0；来自模型卡建议 [S2] |
| 输出 | policy 最多256 tokens，memory updater 最多256 tokens；截断率单报，若影响格式则在开发集修订后锁定 |
| 活动上下文 | 最近8轮交互＋任务＋当前记忆；8是研究配置，不是已有 benchmark 标准 |
| 记忆 | 最多16条结构化事实，包含 entity、attribute、value、source_step、last_updated；保留操作/失败备注的独立字段 |
| 记忆读取 | v0.1把全部16条以内记忆提供给策略；故“进入prompt”与“实际被引用”必须分开记录 |
| 记忆溢出 | 固定FIFO按最近更新时间淘汰；错误消失可能只是淘汰，需单列原因 |
| 解析失败 | 计一次模型调用；无有效环境动作则不伪造工具输出；最多一次格式重试且计成本 |
| 主成功判定 | 环境原生goal/won，不用LLM自评 |

`plan` 文本不代表模型真实内部推理。记忆中的 source_step 是声明的来源，需要日志核对；不能把模型自行引用来源当作可靠因果谱系。

保留一个**无显式持久记忆的 ReAct 式对照**，用于检验残余是否依赖我们加上的记忆结构。该对照不应被称为任何完整记忆方法的复现。

### 3.3 不向策略泄漏的实验信息

真实facts、expert action、gold path、污染标签、错误注入位置、对照分支结果只供实验器使用。策略只接收原有文字反馈、任务、允许的动作说明和自身记忆。v0.1不把每步 admissible_commands 自动塞给策略；它可能提供额外状态线索。需要加入时必须作为明确的新协议对所有臂一致使用。

## 4. Benchmark 与数据选择

### 4.1 ALFWorld：主公开验证环境

使用官方 ALFWorld 的 **TextWorld 文字后端**，不启用 THOR 视觉仿真。它提供家庭物体操作任务，与我们的可验证状态/工具执行需求相符。[S3–S5]

覆盖六类：取放、灯下查看、清洗后放置、加热后放置、冷却后放置、两个物体的取放。第一轮按任务类型分层，防止结果只来自一种任务。

数据来源为官方 `alfworld-download` 分发的 game/PDDL/traj 文件。官方项目介绍3,553个训练任务，ReAct官方 notebook 使用134个 unseen评测实例。[S1,S3] **实际可加载数必须以固定版本manifest为准**：当前 ALFWorld loader 会过滤 movable/Sliced、缺失游戏、缺失 solvable 标记及不可解实例，并受 task_types/num_games限制。不能把公布的原始数量当成本次已加载数量。

拟定分工：

- `train` 中24个实例：工程及机制pilot，原则上每类4个。
- 另24个 `train` 实例：选择提示、窗口、状态特征与模型复杂度。
- 再从 `train` 选120个实例：正式短程状态/恢复参数估计；每类目标20个。以上集合按场景与基础任务分组互斥，最终以manifest校验。
- `valid_seen` 与 `valid_unseen`：冻结后公开环境验证；保持两个split分别报告。正式运行前枚举并保存全部实例，不能边看测试结果边筛选任务。
- 同一基础任务的不同种子、注入点、延迟、恢复分支必须落在同一个数据分区。

这里的“train”用于估计可靠性模型，不训练LLM。若只研究成功正确前缀上可注入的任务，报告总任务数、可达前缀数、注入合格数和失败原因；结论条件于该合格集合。同时保留全split无注入完成率，说明适用覆盖。

**ALFWorld 的长度限制**：实际rollout越长可能正是失败或反复尝试造成的，不能用它充当外生任务长度。可用预先固定的参考解长度做分层，但expert/reference长度不是已证明的最短长度；结果是难度相关分层，不是纯粹的长度因果效应。

### 4.2 Dependency-Workflow：精确控制长度的自建任务族

这是拟实现的工具环境，不是已经存在或已验证的 benchmark。目的仅是提供一个可审计、长度可控的机制试验台，论文不以“新benchmark”作为首要贡献。

**任务定义**：一个工作流包含 \(H\) 个必须依次提交的工作项。每个工作项拥有私有记录，下一项的正确输入依赖上一项正确输出。Agent只能通过工具读取记录、提交工作项、检查状态、修正可修改的提交。

建议工具：`read_record(id)`、`inspect_item(id)`、`submit_item(id, value, parent_receipt)`、`revise_item(id, value, parent_receipt)`、`audit_item(id)`、`finalize()`。

规则由程序在LLM之外生成：

1. 每项有一个小规模离散变换 \(v_i=f_i(v_{i-1},r_i)\)；\(r_i\) 必须由 read_record 获得。值域、变换难度在不同H间固定。
2. 完成第i项后才能开启第i+1项；每项至少一次合法提交，不能通过一个批量调用完成全链。提交回执确认收到，不自动泄露内容是否正确。
3. 最终判定检查每项当前内容与依赖一致性；修改上游后，需要重算受到影响的下游项。保留已做工作的错误依赖，允许错误修复及真实返工成本。
4. `audit_item` 返回该项是否一致及可操作诊断，消耗预算；不强制模型服从错误记忆，允许重新读取和主动校验。
5. 无注入时程序不按我们拟合的随机模型注入随机失败。错误与恢复行为由实际LLM决定。另有按已知随机核生成轨迹的纯simulation，二者分开。
6. 生成器保存完整真值、依赖图、独立随机种子、参考解及校验器。先用程序参考策略证明所生成实例可解，再交给LLM。

规定长度为必须完成的工作项数H；同时记录依赖深度D、参考工具调用数 \(L_{ref}\)、实际调用数t。严格链中D=H，后续可加分叉DAG分开研究工作量和依赖深度，但不放进v0.1。

拟定长度：H∈{4,8,16}估计/开发；H∈{32,64}完全留出。预算 \(B\in\{2L_{ref},4L_{ref}\}\)，每项检验与修复操作均计入。长度改变时保持每项规则分布、错误类型、记忆容量和动作空间不变。

固定16条记忆容量可能使长任务进入短任务未覆盖的淘汰状态。应在短任务校准中预设不同记忆占用量，包括已满但内容正确的初始记忆，覆盖同样的写入/淘汰机制；模型记录占用量和目标条目淘汰事件。如果目标长度仍进入未覆盖状态，要把外推误差归入分布变化，不能称局部参数已充分识别。完整记录与参考解只供环境/evaluator使用，Agent没有绕过工具读取全链的接口。

每个长度拟定60个独立基础种子；短长度各40拟合、20开发，长长度全部测试。相同母实例的不同长度前缀不能跨分区，否则短长度数据已暴露长长度任务内容。正式样本数在pilot精度分析后锁定。

**年龄/暴露操纵**：主运行中的记忆默认全部可见，年龄与prompt暴露会相关。独立识别时，额外设置预先规定的目标条目读取日程：在相同年龄内暴露0、1、4次，并用同长度无关正确条目替换其余位置。这是合成环境中的机制实验，不冒充标准ALFWorld协议。目标条目“出现于输入”的次数可测；“被模型内部使用”不可直接观测，另报可核验的参数/计划引用。

### 4.3 ScienceWorld：后续外部验证

ScienceWorld提供文本科学任务、变体划分、动作与目标进度接口。[S6,S7] 拟选 `boil`、`melt`、`use-thermometer`、`test-conductivity`，先检查各任务是否具备可追踪的事实/工具状态错误与可恢复前缀，再固定变体列表。

官方Python接口包含load/reset、train/dev/test variation函数、gold sequence和goal progress。gold sequence明确不保证最优。保存run history不是保存可恢复的完整模拟器状态。

当前README特别提示1.3.0改变对象枚举顺序以修复随机仿真结果，可能改变轨迹。因而应固定仓库/JAR/JVM版本；不能把不同版本的环境差异误当作LLM误差传播。

ScienceWorld作为**第二阶段环境**，不把它的接入成本压到最小pilot。ALFWorld上有效也不自动意味着跨环境参数直接迁移；ScienceWorld先检验结构复现，零参数跨域迁移另列更强目标。

## 5. 事件、时钟与预测对象

### 5.1 五个必须分开的量

| 符号 | 含义 | 记录方法 |
|---|---|---|
| H | 规定任务工作量 | 自建任务的必需工作项数；ALFWorld用预先定义的任务元信息与参考长度代理 |
| t | 实际环境动作数 | 包括无效动作；另记模型调用数与tokens |
| B | 总预算或landmark后的剩余预算 | 每条结果注明时钟起点，回滚不返还消耗 |
| a | 注入后经过的环境动作数 | 无效动作也计时；不是token距离 |
| n | 错误条目的输入暴露次数 | prompt日志精确计数；参数引用数另列 |

终止事件采用：成功G、明确错误终止F、达到预算仍未完成A。ALFWorld若未提供自然不可逆失败判据，就报告G与A，以及环境明确返回的非成功终止；不把第一次错误动作当作F。

\[
P_G(B)+P_F(B)+P_A(B)=1.
\]

“复发”另定义：在活动上下文已经清除目标错误的landmark之后，该错误或可验证错误后果首次重新进入计划/工具参数。它不等于任务最终失败。

### 5.2 两个不同估计对象

**修复后机制对象**：在相同环境/进度、相同清洁上下文、相同剩余预算b下，比较不同保留记忆：

\[
V_b(u,z)=\Pr(\tau_G\le b,\tau_G<\tau_F\mid U_0=u,Z_0=z).
\]

**完整策略对象**：从注入前开始计费，包含检测延迟、修复成本与回滚返工：

\[
P_{\rm succ}^{\pi,\rho}(H,B)=\Pr(\tau_G\le B,\tau_G<\tau_F\mid\text{预定注入与恢复协议}).
\]

第一个用于隔离机制，第二个用于判断策略实际代价。不能把第一个的优势直接宣称为第二个的优势。

计划延迟修复但提前失败/成功的运行保留在完整策略统计中；不能只选择存活到修复点的运行。landmark条件分析可以做，但明确条件和样本流失。

## 6. 最小模型：两载体污染与任务进度

### 6.1 完整状态与可估计摘要

完整状态W原则上可使过程马尔可夫化，但维度太高。我们拟估计

\[
X_t=(U_t,Z_t,b_t),\quad Z_t=(c_t,m_t)\in\{0,1\}^2.
\]

U包含任务类别、阶段、环境关键状态及剩余工作。c表示活动上下文中存在目标错误或可核验的错误后果，m表示持久记忆中存在该类错误。四个状态为00清洁、10活动污染、01潜伏记忆污染、11两处污染。

这是**候选状态摘要**，不预设它充分。若同样U,Z下后续分布依赖更早历史，需要补充特征或报告抽象误差。世界中的错误状态由U记录，不能仅修好C/M就把整个系统标为清洁。

v0.1预测器可以使用landmark时刻evaluator测得的污染与环境摘要，因此它首先是诊断性可靠性模型。部署时无法观测的特征必须替换成可见估计并重新评价，不能直接宣称在线可部署。整条未来成功率的预测只允许使用预测起点已知状态、预先规定的恢复/暴露规则及已拟合的转移核；不得把测试轨迹未来的实际污染、实际长度或暴露结果作为输入。逐步在线更新预测另列指标。

污染标注依据当前真实状态与错误命题，不以“与干净轨迹文字不同”判错。两条不同的合法执行路径都可以正确。直接注入的根命题可规则判定；派生错误须有可验证依赖，无法确认的标unknown并报告覆盖率。

### 6.2 一个可估计的候选转移核

先考虑没有新增同源错误的单根错误传播。记e_t∈{0,1}表示目标记忆本轮进入策略输入。条件于当前U,c,m，拟设：

\[
p_C=1-[1-(1-\gamma_C)c][1-\alpha e_t m],
\]
\[
p_M=1-[1-(1-\gamma_M)m][1-\beta c].
\]

含义：γ_C、γ_M是目标错误从相应载体消失的概率；α是在暴露时由记忆重新进入活动上下文的概率；β是活动错误被写入记忆的概率。γ_M可包含修正与遗忘，实验需分项记录，两者对有用信息的影响不同。

v0.1假设给定当前状态后的C′、M′独立：

\[
Q(z'\mid z,u,e)=\operatorname{Ber}(c';p_C)\operatorname{Ber}(m';p_M).
\]

这不是文献给出的真实LLM规律，而是最小候选模型。实际调用是顺序更新，若下一步C/M残差存在相关，改用符合调用顺序的条件分解 \(P(m'|z,u)P(c'|m',z,u,e)\)，或在足够数据时估计完整4状态转移。不能仅凭条件独立能得到闭式解就保留错误假设。

根错误消失后仍可能产生无关的新错误。背景错误影响由无注入对照及任务转移核估计；不能把所有后续错误都归于注入。v0.1不对自然错误到达率作结论。

### 6.3 修复算子

恢复策略ρ对应

\[
R_\rho(u',z',b'\mid u,z,b).
\]

它同时记录环境回退、污染残余以及成本。初步的认知载体清理可用残留概率r_C、r_M描述，但两者不必独立。逐载体清理的组合是否可由单独清理预测，是要检验的模块化假设。

若世界、任务进度和剩余预算已经匹配，恢复后污染分布为ω_ρ(z)，则

\[
P_G^\rho(b\mid u)=\sum_z\omega_\rho(z)V_b(u,z).
\]

相对于清洁参考的差值为

\[
\Delta_\rho(b,u)=V_b(u,00)-\sum_z\omega_\rho(z)V_b(u,z).
\]

Δ不先验保证非负。错误内容可能偶然引导到更好路径，完整记忆恢复也可能删除有益知识；单调改善需要额外条件或数据支持。

### 6.4 从过程到任务成功

联合转移核记为Kθ，它包含Q、环境进度变化与执行策略行为。边界为成功态V=1、失败态V=0、非终止且预算为0时V=0。每一步消耗一个统一计量单位时：

\[
V_b(x)=\sum_{x'}K_\theta(x'\mid x)V_{b-1}(x').
\]

对恢复操作成本k，使用V_{b-k}；真实LLM调用成本与环境动作成本分别报表，若压成一个预算需固定权重。总模型也可扩成半马尔可夫费用转移。

该递推是标准动态规划，不是拟主张的新定理。研究价值来自可观测状态、干预可识别的转移/恢复参数，以及这些参数是否支持外推。

## 7. 已可写出的数学锚点与待完成理论

### 7.1 数学锚点 A：完整清除的充分条件

**条件**：修复后W中所有未来相关状态的联合分布等于干净参考，包括环境、上下文、记忆、缓存、控制器、随机机制与剩余预算；之后使用相同策略和环境核。

**结论**：所有未来轨迹事件分布相同，特别是相同预算内任务成功率相同。

**证明要点**：初始分布相同，一步转移核相同，归纳得到任意有限轨迹的联合分布相同。

若修复后完整状态分布与参考的总变差距离至多ε₀，则任意未来事件概率差至多ε₀。这是同一马尔可夫核对总变差的收缩性质；不能把完整状态TV与几个污染bit的距离混淆，也不能断言完整状态TV会被后续相同核放大。

**实验作用**：完整恢复臂是边界检查。如果它与同状态同预算的clean reference存在系统差异，首先查未恢复状态、预算/随机流或评测器，不马上解释为新机制。

### 7.2 数学锚点 B：单条潜伏记忆的复发概率

假定活动上下文已清洁，仅一条目标错误仍在记忆里；尚未复发期间，每一步以概率r暴露并激活该错误。若没有激活，再以概率d清除错误；清除与首次激活都结束潜伏过程。没有补写和其他同源载体。

设s=(1-r)(1-d)，则

\[
\Pr(\tau_{\rm relapse}\le k)=\sum_{j=1}^{k}s^{j-1}r
=\frac{r(1-s^k)}{1-s},\quad s\ne1.
\]

s=1时r=d=0，复发概率为0。若修复后该条错误存在概率为q，且不存在时没有同源复发，上式乘q。

变动暴露日程下，令r_j=αe_j：

\[
\Pr(\tau_{\rm relapse}\le k)
=q\sum_{j=1}^{k}r_j\prod_{\ell<j}(1-r_\ell)(1-d_\ell).
\]

**解释**：残留概率q、重新激活r和清除d具有不同作用；相同年龄可以对应不同复发风险。只有d=0且激活概率恒定等特殊条件下，才简化成几何式。它预测复发，不能直接当成任务失败率。

这是基本竞争风险求和的推导，作为模型的可解特例和检查点，不宣称其本身有理论新颖性。首次复发之后的修复、返工与成功由第6.4节处理。

### 7.3 数学锚点 C：有限预算预测误差

对同一完整/充分扩展状态空间，假设真核K与估计核K̂在所有相关状态的一步TV距离至多ε，初始状态分布误差至多δ₀。通过逐步最大耦合：

\[
|P_G(B)-\widehat P_G(B)|
\le1-(1-\delta_0)(1-\epsilon)^B
\le\delta_0+B\epsilon.
\]

证明要点：两条轨迹初始匹配概率至少1−δ₀；匹配时每步继续匹配概率至少1−ε；成功标签在全程匹配时一致。取补事件得到界。

这解释了为什么短程拟合不错仍可能长程失准。若使用粗状态摘要，ε必须包含状态抽象误差与目标任务分布变化，不只是参数估计误差。小样本经验误差无法自动给出上述全状态一致上界。

此界也是标准耦合工具。本研究需要进一步争取的是：利用可观测残余与恢复结构得到更有信息量的界，并区分何种局部参数能跨长度复用。

### 7.4 正式理论的三个目标

| 目标 | 需要额外解决的难点 | 对应可检验预测 |
|---|---|---|
| T1 部分恢复的结构化风险界 | 载体清理质量、错误依赖与任务进度怎样约束V的差值；有益记忆损失如何进入费用 | 相同粗错误量，不同载体/暴露的恢复后风险不同 |
| T2 复发到任务失败 | 复发可能被纠正，返工消耗预算；不能假定每次复发致命 | 复发率相近但剩余工作/预算不同，完成率不同 |
| T3 可组合预测条件 | 识别局部转移与修复算子后，何时组合适用于未见长度/修复条件 | 固定参数的长程预测与留出恢复组合预测 |

当前三条锚点有推导，但T1–T3尚未完成。若最后只剩通用DP和上述基本界，理论贡献仍偏弱，需要依靠新的可识别结构或更强的结果继续推进。

## 8. 错误注入、恢复臂与公平比较

### 8.1 第一类错误与注入位置

ALFWorld第一轮采用**错误物体位置/状态事实**，不注入指令攻击，不改任务目标。优先选择已经通过工具观察核实过的事实，把一个记忆值替换为一个环境内存在但错误的值，其他字段与文本长度尽量匹配。

例如已观察到某物体在容器A，记忆却记为容器B。A、B必须真实存在，目标事实具有后续可用性。若需要“可用”判据，使用任务规则/参考依赖预定义，不按最终失败情况挑选注入。

初次直接写记忆，是研究M→C传播的可控干预，结论条件于已形成错误记忆。后续再增加错误工具反馈→自然写入记忆的路径，报告写入成功率；不能用直接写入实验估计自然错误出现频率。

另设等长度正确事实替换的sham注入，排除单纯编辑/提示位置影响。无注入运行检验原生基线能力。

### 8.2 共享前缀与四个恢复臂

保存注入前正确检查点 \((E_0,C_0,M_0)\)，在同一基础任务产生注入后的传播轨迹，延迟a步后保存 \((E_a,C_a,M_a)\)。随后从该父轨迹分出四个恢复臂：

| 臂 | 环境与活动上下文 | 记忆 | 回答的问题 |
|---|---|---|---|
| R0 不恢复 | 保留E_a,C_a | M_a | 不采取恢复的策略结果 |
| R1 回滚后保留记忆 | 恢复E_0,C_0 | 保留M_a，经共同的回滚有效性处理 | 环境/上下文恢复后仍残留多少风险 |
| R2 回滚后清理目标错误 | 与R1完全相同 | 在R1记忆上由oracle只修正目标错误及可验证错误后果，保留其他内容 | 隔离目标残余污染的作用 |
| R3 完整检查点恢复 | 恢复E_0,C_0 | 恢复M_0 | 完整清除边界及有益经验丢失代价 |

R1和R2使用相同的、无需访问目标错误真值的回滚有效性规则：依赖已撤销动作的状态事实标为“需重新验证”，静态观察按规则保留。这样避免人为让所有回滚记忆都过时。该规则不保证识别注入错误，是否阻断其传播由结果决定。

R2是oracle机制干预，需要真值；它不是可部署修复器，也不是RIR的完整复现。R1/R2核心比较中，修正目标事实不删除其他有用事实；另记录token差异，必要时加入sham语义保持改写。

R3同时删除了潜在有益的新知识。因此R3与R1的成功率差不能全部归因于“错误清除”；R2与R1才是首要残余效应比较。

### 8.3 时钟与成本

机制分析中，R1/R2/R3从恢复后landmark开始，给予相同剩余环境动作预算b=32；R0只作另一个实际状态的策略参考，不与R1/R2形成“纯记忆效应”对比。

策略分析另设从注入前开始的总预算B=80环境动作，并记录最多2B次常规LLM调用及格式重试额外调用。恢复消耗的LLM调用、tokens、环境重放步数和墙钟时间分别报出。oracle清理不能与真实修复器在成本上直接竞争。

b=32、B=80是pilot配置。若clean运行出现能力地板或大量合理完成被预算截断，只可在开发阶段依据clean日志修订，之后所有臂统一冻结。

延迟修复前已经终止的轨迹，不再强行产生续跑；它们进入总策略成功/失败分母。条件于到达landmark的机制分析单列。

### 8.4 回滚实现与一致性门槛

ALFWorld适配器采用固定gamefile/seed重新初始化，再重放记录下的动作前缀。恢复不重新询问LLM生成前缀。C/M为序列化的显式对象，工具缓存和控制器状态一并恢复。

已核验的官方ALFWorld高层适配器提供reset/step与游戏注册，未在该层看到可直接依赖的完整中途snapshot API。故“重置＋重放”是我们的实施方案，仍需实测可重复性，不是已确认可运行的回滚实现。

接口验收：10个基础任务，每个选2个前缀，每个重放2次，共40次恢复；核对观察、reward/done、规范化环境facts、任务状态与后续固定动作响应。恢复后的外部预算计数由runner持有，避免reset把预算返还。若只能核对文本而无法检查facts，称“观察一致”，不能声称完整状态一致。

重放检验失败时先修adapter与版本固定，不运行大批LLM分支。ScienceWorld亦执行该门槛，尤其检查JAR/JVM与对象顺序。

## 9. 第一轮实验：最小但可判别

### E0：能力与工程检查

24个train基础实例，六类各4个，1个固定seed。先运行clean与sham条件，检查目标事实可追踪、任务可完成、恢复接口一致、上下文与记忆格式可用。

开发期操作判据：若24个clean实例成功少于8个，先检查动作格式、提示、预算与环境adapter；确认无实现问题后才考虑切换14B或收窄任务。该数值是工程决策阈值，不是统计显著性标准。若接近满分，仍可通过注入/返工预算观察残余效应，不必人为降低模型能力。

### E1：残余机制pilot

- 使用24个基础实例。
- 延迟a∈{2,6}个环境动作。
- 四个恢复臂R0–R3。
- 每个基础实例与延迟先生成一个共同的传播父轨迹，再分支。
- 1个续跑seed：最多24×2×4=192条恢复/不恢复续跑；再加24个clean及24个sham参考，共最多240条。前缀与提前终止数另报。
- 对照clean reference需与R3的同状态同预算边界相匹配；完整任务clean baseline可复用前缀但不是同一个估计对象。
- 若机制值得继续，追加至3个续跑seed：最多576条分支＋72个clean＋72个sham，共720条；基础任务仍只有24个，不能当720个独立任务。

主测量：R1−R2的成功率差、复发累积发生率、首次复发时间、恢复后错误参数引用、返工动作及tokens。R3的边界一致性单独检查。

如果仅从E1看到R2成功率更高，只支持残余清理有作用，尚不证明四状态模型或跨长度规律。

### E2：识别转移与检验状态摘要

用正式校准集采集一步/短段转移，拟合α、β、γ_C、γ_M与任务进度核。先按任务阶段共享参数，参数量受有效转移次数限制；不要把小样本扩成每任务每年龄一套参数。

检查：同样U,Z后，一步预测是否仍依赖历史；C/M下一步残差是否相关；错误年龄a和输入暴露n是否改善留出预测。行为引用是结果变量，不能默认作为事前已知暴露。

年龄字段分别保存距根错误注入的动作数、距最近修复的动作数；两者不能在模型中混写成同一个a。参数识别需要各相关转移有足够覆盖：例如始终不暴露记忆的数据不能识别α，始终没有活动错误的数据不能识别β。缺少覆盖时补针对性短程干预，不依赖最终成功率反推所有参数。

### E3：冻结后的长度预测

在Dependency-Workflow的H=4/8/16上估计参数和选模型。冻结参数、状态规则与恢复算子后，在H=32/64上运行真实LLM轨迹并评价。

另外按同样核生成大量模拟轨迹，用来验证计算、近似与理论边界。**纯simulation的良好拟合不能替代E3的LLM外推。**

### E4：留出恢复条件

校准阶段分别估计活动上下文清理和记忆清理的组件作用；测试未拟合的联合清理、未见延迟或清理强度。只有先给出组件作用与组合规则，才可以称“预测未见恢复条件”。一个全新黑箱修复器若没有任何参数/机制信息，不能直接零样本预测。

R1/R2配对机制pilot与E4分开：pilot可用于发现/开发，正式留出联合条件必须用不同基础任务，且不能再调整组合规则。

## 10. 预测基线、评价与样本决策

| 模型 | 输入/结构 | 作用 |
|---|---|---|
| M0 几何衰减 | 固定局部失误率，\(p^H\)；任务/预算条件明确 | 展示独立致命错误假设的局限；不作为唯一对手 |
| M1 粗状态首达模型 | 相同进度/预算特征U，不区分C/M污染 | 公平检验污染状态是否提供额外信息；属于我们实现的标准吸收模型，不冒充TraceToChain完整复现 |
| M2 两载体过程模型 | U＋(c,m)，转移与恢复核 | 主模型 |
| M3 年龄/暴露扩展 | M2＋a＋n及必要交互 | 检验年龄是否必要；不预定它胜出 |
| M4 直接预测基线 | 与M2/M3相同可用特征的正则化logistic或离散时间hazard模型 | 检验机制分解是否优于直接拟合结果；在开发集选定复杂度 |

所有模型使用相同训练/开发/测试划分、相同允许的信息。logistic不被限制成只能用长度，以免人为削弱对手。若正式宣称优于TraceToChain或RIR，须另实现其完整方法并核验配置，当前不作该宣称。

主指标：冻结后测试集Brier score、log-loss、校准偏差；分长度/恢复臂的成功率预测误差；复发累积发生率曲线误差。另报G/F/A三类概率与实际频率。对模型选择，优先使用概率质量，而非单次硬分类准确率。

区间以基础任务为cluster作配对bootstrap；种子与分支嵌套在task内。结束前未复发的任务按成功终止/失败终止分别作为竞争事件处理；预算结束是有限窗口，不把所有终止都当作非信息删失。

pilot没有足够能力保证发现小幅成功率差。对配对二元成功指标D∈{−1,0,1}，用pilot估计Var(D)，以目标半宽h作粗略规划 \(n\approx1.96^2\operatorname{Var}(D)/h^2\)，再按cluster和任务分层修正。h=0.10可作首个成本估计，正式论文若要解释更小差异应增加独立任务。不能用“p>0.05”宣布机制不存在。

继续/调整判据：

- R1/R2出现可重复残余差异且方向在任务类型中可解释：进入正式模型校准。
- 差异不确定但区间很宽：追加独立任务，避免反复增加相同任务的seed冒充覆盖。
- 残余存在，M2不优于M1/M4：检查状态摘要、可观测性和任务进度；不以更多自由参数逐曲线补拟合。
- M3没有留出收益：删年龄项。
- 只在已拟合H内有效：保留局部机制结论，不能宣称外推已成立。

## 11. 运行日志与接口契约

拟实现接口：

```python
reset(task_id, env_seed) -> observation, public_info
step(action) -> observation, reward, terminated, truncated, public_info
checkpoint() -> opaque_checkpoint
restore(checkpoint) -> RestoreReport
audit_truth() -> evaluator_only_state
inject(target_fact, wrong_value) -> InjectionRecord

```

这些是待实现的研究runner接口，不是声称ALFWorld原生具有这些方法。

每步JSONL最少字段：`task_id, scene_id, split, model_revision, prompt_hash, seed, parent_branch_id, injection_id, repair_arm, env_step, llm_call, remaining_budget, observation, action, memory_before, memory_after, target_present_C, target_present_M, target_exposed, target_referenced, task_progress, reward, terminated, truncated, input_tokens, output_tokens, latency_ms, checkpoint_hash`。

额外保存：注入前truth、注入编辑diff、各次恢复组件清单、可验证派生关系、unknown标注、前缀重放校验。策略输入日志与evaluator-only日志分开，确保真值未进入LLM提示。

版本manifest包含：代码commit、Python/依赖锁、环境数据hash、模型/tokenizer revision、推理引擎与精度、提示hash、实例清单及分组划分、所有预算与采样配置。版本未固定前只可做开发运行。

## 12. 理论、simulation与论文行文的对应

| 论文位置 | 要写清楚的内容 | 对应产出 |
|---|---|---|
| Introduction | 恢复环境/上下文后，保留信息仍可能影响未来；现有工作之间缺少可测试的任务结果连接 | 残余干预案例＋研究问题 |
| Setup | 完整状态、两载体摘要、H/t/B、复发与目标完成 | 定义、runner与数据协议 |
| Theory | 清除边界、残余传播与有限预算成功、外推所需条件 | 正式命题及假设，区分基本工具与新结果 |
| Simulation | 已知核下的闭式检查、参数作用、模型失配与边界 | 概率守恒、近似误差、成功/复发曲线 |
| Agent experiments | R1/R2机制、ALFWorld验证、受控长度预测 | 配对差异、校准、留出结果 |
| Scope | 任务内记忆、文本工具环境、条件于注入的结论 | 自然错误率、跨域参数和真实修复器的边界 |

Simulation至少包含：不同记忆残留q、激活α、清除γ、回写β；修复频率与预算；相同错误数量不同载体分布；生成核含历史依赖而拟合核不含的失配情形。参数网格先用于机制覆盖，不根据真实测试结果反向选择有利区域。

拟画四张核心图：恢复后的复发曲线；R1/R2配对任务结果；短长度拟合/长长度预测；污染/年龄/暴露消融。所有实测图待真实数据生成，当前不填结果。

## English synopsis

We propose a mechanism-and-prediction study of residual errors after agent recovery. The initial system is an instrumented ReAct-style agent with explicit within-task memory, using frozen Qwen3-8B. ALFWorld's text backend provides the primary public evaluation; a newly specified dependency-workflow environment provides controlled task lengths. ScienceWorld and Qwen3-14B are later validation stages.

The minimal model separates active-context contamination, persistent-memory contamination, task state, and remaining budget. The key intervention compares identical environment/context rollbacks with either retained memory or oracle removal of the target error. Full checkpoint restoration supplies a boundary condition. Primary evidence is calibrated, parameter-frozen prediction on held-out lengths and recovery conditions, rather than benchmark SOTA. The protocol and elementary mathematical anchors are complete; agent deployment, measurements, and the proposed substantive theoretical results remain future work.
